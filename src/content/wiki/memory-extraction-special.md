## 一句话

记忆抽取 = 按**价值映射**决定抽什么（信息源）+ 按**粒度模型**决定存成什么样（三层）+ 按**场景配置**决定什么时候抽（时机）+ 用「检索-判定-操作」保证进得对（门控）；主动检索增强、渐进式缓存、格式转换、JSON Schema 与结构化提示词是让流水线跑起来的五块基石。

## 核心框架

### 1. 四类信息来源与价值映射

| 来源 | 可信度 | 记忆价值 | 策略 |
| --- | --- | --- | --- |
| 显式信息（直接说出的事实/偏好/计划） | 高 | 高 | 必抽 + 指代消解 |
| 隐式信息（行为/语气/频次推断） | 中 | 高（画像核心） | 带置信度，多次出现才沉淀 |
| 模型内部（激活向量/推理轨迹） | 中 | 中（研究价值） | 只做辅助信号，不直接入库 |
| 环境状态（时间/地点/设备） | 高 | 低（单独）→ 高（绑定） | 作为场景标签/时间戳附加 |

隐式信息铁律：**单次出现是噪音，多次出现才是信号**，推断类记忆要带 `confidence` 并等验证后再转正。

### 2. 混合粒度分层模型

- **语义片段级**：可检索的最小语义单元，向量化存储。相当于 RAG 的**查询改写**——抽取时就把对话改写成利于未来检索的伪查询形态；适合 embedding 模糊语义检索，片段短而聚焦能显著提高重排准确率。
- **实体事实级**：实体+事实的结构化条目/图谱三元组，精确检索主战场。两条转换路径：①语义聚合（片段→向量→聚类合并成事实）②结构化抽取（文本→(实体,关系,属性)→Neo4j 图谱 merge）。
- **摘要级**：120-200 字用户视角自然段（JSON 里的 `summary`），用于上下文恢复与概览。

三层递进：片段反复出现 → 聚合升格为实体事实 → 压缩归纳为摘要。工程默认组合：片段级打底（召回）+ 实体事实级精确层（答对）+ 摘要级概览层（省 token）。

### 3. 粒度与时机配置

时机三模式：**同步**（轮级，关键信息密集）/ **异步**（会话结束批处理，长期记忆）/ **事件驱动**（关键节点触发，生产默认主干 + 会话结束补抽兜底）。

| 场景 | 粒度组合 | 时机 |
| --- | --- | --- |
| 个人助理 | 实体事实级 + 摘要级 | 异步 + 关键决定事件驱动 |
| 编程助手 | 片段级 + 实体事实级 | 事件驱动（提交/报错/重构） |
| 客服/销售 | 实体事实级 + 摘要级 | 同步 |
| 研究/阅读助手 | 摘要级 + 片段级 | 异步 |
| 游戏 NPC | 片段级 + 摘要级 | 事件驱动 |
| 多 Agent 协作 | 摘要级 + 实体事实级 | 事件驱动 |

成本旋钮：频率（同步→事件驱动→异步）、输入（只抽增量）、粒度（按需开层）。经验法则：召回不够→加片段级；精确不够→加实体事实级；token 超标→升摘要级、降频率。

### 4. 主动检索增强

抽取也需要检索：指代消解要历史、事实验证要历史、去重要历史。三个插入点：

- **前置检索**：抽取前用对话片段召回历史记忆，拼进 prompt；
- **中置检索**：ReAct 循环中模型自主决定检索（`SearchContext` 工具）；
- **后置检索**：候选与历史库比对（即「检索-判定-操作」）。

收益：指代消解率↑、重复存储↓、决策可审计（thought trace）。代价：多轮 LLM 调用，适合高价值对话，低价值用 Simple 一次性抽取。

### 5. 渐进式缓存（MemoryBuffer）

跨轮次碎片信息先攒后提交：`UpdateBuffer` 暂存（返回 `BUFFERED`）→ 缓冲区内容进后续抽取上下文 → 证据凑齐 `CommitMemory` 合并提交并清空。生命周期：暂存 → 补全 → 提交 / 超时清理（上限 ~20 碎片或 N 会话）。与 MemGPT 分层记忆思想同源：不急着把碎片写死，等它长成完整记忆再入库。

### 6. 格式转换链路

多格式输入 → 规范化 `ConversationMessage` → LLM 抽取 JSON → `MemoryItem` 字段化 → embedding 向量（Milvus）/ 三元组（Neo4j）双写。细节：向量编码用 `key + value` 拼接（标题侧+细节侧，召回更稳）；每跳转换保留溯源（来源消息 id + 时间戳）。

### 7. 检索-判定-操作（写入门控）

候选进库前必经四步：①前置检索（候选 key/value 检索历史）→ ②差异对比（完全重复/部分重叠/语义冲突/全新）→ ③工具选择（Insert/Update/ResolveConflict/Skip，能更新不新增）→ ④执行与反馈（写入+审计+回传）。原则：**记忆库条目数增长要克制，质量比数量重要**。

### 8. 候选生成标准流程

输入规范化 → 增量切分 → 语言检测选模板 → 上下文组装（当前对话+历史检索+缓冲区）→ LLM 抽取（Simple/ReAct）→ JSON 解析校验 → 门控提交。

结果五态状态机：`SUCCESS` / `BUFFERED` / `IGNORED` / `TIMEOUT` / `FAILED`——只有 SUCCESS 才自动入库，其余状态都要可观测。

### 9. JSON Schema 契约

LLM 输出：`{ memory_list: [{key, memory_type: LongTermMemory|UserMemory, value, tags[]}], summary }`。入库扩展字段：`id / user_id / session_id / source_message_ids / event_time / confidence / source_type / status`。ReAct 每步输出决策对象：`{thought, action: SearchContext|UpdateBuffer|CommitMemory|Ignore, action_params}`。

### 10. 结构化提示词四要素

角色定义（从用户视角抽）→ 任务目标 → 处理规则（**指代消解四连**：相对时间→绝对时间、事件时间≠消息时间、地点保留、代词全解析；强制第三人称；完整性优先）→ 输出约束（完整 JSON 结构 + 高质量 Few-shot 演示最难的时间转换 + 语言适配中英模板 + 只输出 JSON）。

## 核心实现（MemBook Chapter_4）

- `MemoryExtractor`：主入口，`strategy` 切换 simple/react，只有 SUCCESS 才双写入库（Milvus 向量 + Neo4j 图谱）；
- `SimpleExtractor`：一次性抽取，`detect_lang` 选模板，`parse_json` 失败返回 FAILED 不抛异常；
- `ReActExtractor`：有界循环（max_steps 兜底 TIMEOUT），四工具分发，`SearchContext` 实现向量检索+图谱取详情，thought_trace 全程可审计；
- `detect_lang`：清洗角色标记/时间戳后统计中文字符占比，>30% 判中文，零成本零模型。

## 失败模式与防御

抽取幻觉/组织幻觉/检索幻觉/更新幻觉/隐私泄露（PII）/注入攻击 六类。防御按流水线位置：抽取前输入清洗+PII 检测；抽取中显式/隐式分通道+引用式抽取；抽取后事实校验+幻觉检测；存储时敏感字段掩码+权限标签+审计日志。原则：**能不入库的敏感信息就不入库**，掩码优于加密。

## 评测

离线黄金对话集（50-100 条，覆盖偏好/计划/多轮指代/闲聊/敏感信息五类）回归六项指标：召回率、精确率、检索命中率、更新正确率、重复条目率、token 成本。改提示词或换模型后必跑。

## 与 RAG 的关系

记忆抽取是 RAG 的**写入端**：RAG 管怎么查出来，抽取管怎么存进去。抽取时做指代消解，查询改写才省力；查询改写做好，语义片段级的伪查询设计才能发挥价值。一个完整的记忆系统一定是「抽得好 + 查得准」的双端工程。

## 落地建议

从「Simple 抽取器 + 检索-判定-操作门控」起步，跑通后再上 ReAct 与渐进式缓存——先把写入链路做干净，再追求抽取的聪明。
