> Agent Memory 不是"存储"，而是一个把历史转成可用信息并影响决策的闭环系统。

## 一、Memory 的三个核心命题

Agent 里的 Memory 要回答的问题是：**过去有没有帮它把今天的事做对**。靠一个 Markdown 文件甚至一个数据库都远远不够——Agent 需要一个小的 **Memory OS**。

经过近年来的探索，Agent Memory OS 可以抽象为三个词：**Raw Ledger、Views、Policy**，分别类比操作系统里的原始日志、索引与缓存、调度规则。

### 命题 A：Memory 不是"存储"，而是可被决策利用的外部状态

如果把 Agent 看成一个从输入到输出的函数，仅仅"存了很多历史"并不构成能力。能力来自：在当前状态下，历史能否以某种形式影响决策分布。

Memory 的价值不在于"存了多少历史"，而在于**这条从历史到当前决策的通道是否有效**。它要么进入上下文（证据/摘要/子图），要么直接参与决策（例如对输出分布做调制）。

### 命题 B：Memory 的最小闭包是 Ledger、Views、Policy

| 组件 | 类比 | 职责 |
|------|------|------|
| **Raw Ledger** | 账本/黑匣子 | 按发生顺序保留写入、修改、删除和反馈，可审计 |
| **Derived Views** | 缓存+索引+物化视图 | 从账本加工出的各种"便于查找的版本"：向量索引、全文索引、知识图谱、时间线 |
| **Policy** | 调度器/控制回路 | 决定何时读、读多少、何时写、如何更新、如何遗忘 |

三者缺一，系统要么不可治理（没有账本），要么不可用（没有索引/抽象），要么不可持续迭代（没有可 A/B 的控制点）。

### 命题 C：Memory 的基本单位是 event 序列

最通用的 ledger 事件应包含：作用域（scope）、时间戳、输入观测、系统动作、记忆变更（ADD/UPDATE/DELETE/NONE）、反馈信号、决策元数据。

Event 序列是"真相来源"，但太底层。真正把历史变成能力的是 **views**（对 event 的重组织/压缩/索引/技能化）和 **policy**（决定触发哪些 view、怎么更新）。

因此，Memory 的本质是一个闭环系统：

---

> **核心闭环**：Raw Ledger（权威）→ Views（可用）→ Policy（控制）→ Commit（回写）→ Provenance（可回放）

## 二、System 1 + System 2 的双系统设计

### 为什么需要"非空"的 System 2

- **System 1**：快速工作的通用 Agent（大模型+工具），读懂问题、写代码、调用搜索、生成回答
- **System 2**：较慢的外部记忆回路，负责保存、检索、更新、压缩和遗忘，像操作系统内核与后台服务

如果 System 2 不发挥作用，记忆能力只能通过 RL post-training 固化到 LLM 权重中，很难保证特化后仍保持通用泛化能力。

### "记忆能力"与"Agent 通用能力"为什么是"相对正交"的

**正交的一侧**：同一个 base model 接入不同记忆策略就能显著改变长程表现；而同一套记忆 infra 也往往能服务多种不同的 base model。这种跨模型可复用意味着能力更多绑定在接口与外部状态上。

**非正交的边界**：检索噪声、错检、时序冲突会直接破坏推理（引发幻觉）；同时检索策略依赖 Agent 的自我评估能力。因此更准确的说法是"相对正交 + 存在可控交叉项"，而 System 2 的可观测性、可回放能力正是将交叉项显式化、可诊断。

### 非参数化逼近参数化 Memory

参数化记忆（parametric memory）：经验写进模型权重（训练/微调），推理时不需要额外检索。
非参数化记忆（non-parametric memory）：经验写在外部状态里（ledger + views + skill pool），通过检索/聚合/注入影响决策。

System 2 的意义就是：**把在线适应的主战场从模型权重挪到外部记忆状态与控制策略上**。

**记忆对决策的调制方式**：新的动作倾向 = 模型原本的判断 + 记忆带来的修正 Δ（Delta）

Δ 是"外置的可控偏置"——不需要改模型权重，但能改变决策分布。

## 三、非参数化 Memory 的上限由什么决定

### 1. 接口带宽（注入容量）

无论是 passage、graph、skill，最终都要通过 Context Bridge 让 System 1 用上它。注入通道存在预算约束——外部记忆再大也没用，真正起作用的是每一步你注入多少有效信息。

### 2. 检索与聚合误差

Views 是从 Raw Ledger 派生出的近似结构。近似会带来错检、漏检、时序冲突、语义漂移，直接污染修正项 Δ。因此上限不仅取决于"存了多少"，更取决于误差是否能被治理（可观测、可溯源、可回放）。

### 3. Policy 的学习与控制

存太多污染，存太少学不到；召回太多挤占上下文，召回太少缺证据；错删一条长期偏好，个性化一路歪下去。

非参数化 Memory 的真正瓶颈往往不是存储后端，而是 **policy**。

## 四、核心模块设计

### Policy 层：Rubrics 不可持续

打破传统 engineers 的思维禁锢：基于预定义规则（rubrics）的 policy 不可持续，必须用 model 来处理。目前最可行的路径是 **Agentic Memory**——将记忆操作彻底工具化，整合进 Agent 的动作空间，让模型像控制手臂一样控制记忆。

记忆工具分类：

| 记忆层 | 操作 | 功能 | 对应参数化行为 |
|--------|------|------|---------------|
| 长期记忆 (LTM) | ADD | 存储新知识 | 梯度更新 |
| LTM | UPDATE | 修正旧知识 | 权重调整 |
| LTM | DELETE | 移除过时信息 | 剪枝 |
| 短期记忆 (STM) | RETRIEVE | 语义搜索并注入 | 激活相关神经元 |
| STM | SUMMARY | 压缩对话历史 | 抽象表征 |
| STM | FILTER | 移除无关 Context | 注意力机制 |

### 关键工作：AgeMem 的分阶段 RL 训练

Agent 同时面对长期记忆和眼前上下文时，很难一上来就用好整套记忆工具。AgeMem 采用分阶段训练：
1. 练长期记忆——判断什么值得新增、什么是修正
2. 练短期管理——过滤和摘要
3. 把长期检索与短期整理放进复杂任务

### 记忆单元的结构、时序和压缩

**SimpleMem** 不存储原始文本，而是存储压缩后的"记忆单元"。基于亲和力评分在后台异步执行递归固化，将高亲和力的记忆单元合并为更高层级的抽象表征。据说在长时序多轮对话任务上以约 1/10 的 token 消耗击败了全量上下文。

**时序记忆**："拜登是美国总统"在 2024 年可能没什么问题，2026 年就不对了。Zep 及其引擎 Graphiti 引入了时序知识图谱，对边加入时间标注（Temporal Validity），在检索时结合查询时间语境动态合成"当前时刻"的真值图谱。在其报告的长时序评测上可提升 18.5% 准确率。

**分层记忆（MemWeaver）**：同一段历史需要不同抽象——图记忆（关系）、经验记忆（模式）、片段记忆（原文）。三者都来自同一段历史，却服务于不同问题。

### 程序性记忆：从"知识"到"技能"

事实记忆回答"是什么"，长程任务还需要"怎么做"。**ProcMEM** 用 Skill-MDP 描述技能：触发条件→动作序列→终止条件。用 PPO 风格门控做反事实验证，确保新技能不偏离旧技能太远。

### 记忆整合层

**LycheeMemory**：把外部内容变成潜层 Token，以接近 KV-Cache 的形式注入注意力计算，减少文本编解码开销。
**MemAdapter**：从图谱中取出相关局部子图，对齐到模型的语义空间，不用微调主模型也能融合异构记忆。

## 五、架构五件套

1. **内核（Kernel / Control Plane）**：System 2 的慢回路与调度器，决定何时检索/写入/更新
2. **文件系统（File System / Storage Plane）**：Raw Ledger + Views，承载时序一致性与语义压缩
3. **可执行文件（Executable / Skill Plane）**：把经验固化成可复用的程序性单元
4. **总线接口（Interface / Context Bridge）**：记忆与推理之间的接口层，低开销低失真地注入
5. **学习引擎（Learning Engine）**：在不更新权重的前提下，把交互反馈转为改进信号

## 六、工程落地：PowerMem

PowerMem（[GitHub](https://github.com/oceanbase/powermem)）是这套 Memory OS 的开源工程落点，面向 AI Agent 提供持久化、自演化的记忆能力。

**会话结束，状态还在**：持久化记忆、用户画像和作用域管理，记忆可按用户与 Agent 隔离。

**多模态检索**：向量检索、全文检索、图检索、新近度信号参与混合检索——对应 Views 的设计。

**生命周期管理**：大模型参与记忆抽取、更新、合并，结合艾宾浩斯式时间衰减调整优先级。

**经验→技能蒸馏**：Experience 保存经验，Skill 把反复验证的经验整理成可复用的做法。

**多入口接入**：提供 Python SDK、HTTP 服务、MCP 和 CLI，支持 OceanBase、SQLite、PostgreSQL 等后端。

一个长期运行的 Agent，可以顺着几个问题检查自己的记忆系统：
- 会话结束后状态还在不在？
- 历史是否只有向量这一种查法？
- 旧事实能否更新，低价值内容会退场吗？
- 成功经验能沉淀成技能吗？
- 多个应用能共用同一套记忆底座吗？

## 七、2026 全面综述：Memory for Autonomous LLM Agents

arXiv [2603.07670](https://arxiv.org/abs/2603.07670)（[HTML 全文](https://arxiv.org/html/2603.07670)）是一篇 2026 年初发表的全面综述，覆盖了 2022–2026 年 Agent Memory 领域的核心进展。它提供了一个与前三节互补的视角：用 **POMDP** 形式化重新组织了整个领域，并给出了系统化的三维分类学。

### 7.1 形式化：Write-Manage-Read 循环

将 Agent 循环写成：

- $a_t = \pi_\theta(x_t, \mathcal{R}(M_t, x_t), g_t)$
- $M_{t+1} = \mathcal{U}(M_t, x_t, a_t, o_t, r_t)$

其中 $\pi_\theta$ 是策略（LLM），$\mathcal{R}$ 从记忆读取，$\mathcal{U}$ 写入并管理记忆，$g_t$ 是目标，$o_t$ 是环境反馈，$r_t$ 是奖励信号。

关键洞察：$\mathcal{U}$ 不是简单 append — 它要摘要、去重、打分优先级、消解矛盾、适时删除。且 $\pi_\theta$ 与 $(\mathcal{R}, \mathcal{U})$ 构成因果闭环：决策决定写什么，写什么又塑造未来决策。

### 7.2 三维分类学

**时间范围（Temporal Scope）：**
- **Working memory**：上下文窗口内的内容，完美召回但容量有限
- **Episodic memory**：具体的交互记录（工具调用、对话轮次、环境观察），带时间戳和重要性评分
- **Semantic memory**：去上下文的抽象知识（"用户偏好 DD/MM/YYYY"），需主动固化
- **Procedural memory**：可复用的技能和可执行计划（Voyager 的技能库）

**表示底层（Representational Substrate）：**
- **Context-resident text**：摘要、scratchpad，零基础设施但容量受限
- **Vector-indexed stores**：稠密嵌入 + 近似最近邻搜索，可扩至百万级但丢失结构化关系
- **Structured stores**：SQL/知识图谱，保关系但需预定义 schema
- **Executable repositories**：代码库/工具定义，可直接调用

**控制策略（Control Policy）：**
- **Heuristic control**：硬编码规则（top-k、每 n 轮摘要）
- **Prompted self-control**：记忆操作作为工具暴露给 LLM，由 LLM 决定何时调用（MemGPT 方式）
- **Learned control**：记忆操作作为策略动作进行端到端优化（AgeMem 的三阶段 RL）

### 7.3 五大机制家族

| 机制 | 代表工作 | 核心思想 | 风险 |
|------|---------|---------|------|
| Context-resident compression | Self-Controlled Memory | 摘要/滑动窗口/层次摘要 | 摘要漂移：低频关键信息逐轮消失 |
| Retrieval-augmented stores | RAG, RET-LLM | 外部存储 + 检索注入 | 检索质量瓶颈：趋近而非有用 |
| Reflective self-improvement | Reflexion, ExpeL, Generative Agents | 自然语言事后复盘、聚类反思 | 自强化错误：错误信念固化 |
| Hierarchical virtual context | MemGPT, JARVIS-1 | OS 虚拟内存式分页管理 | Orchestration 失效：分页错误无声积累 |
| Policy-learned management | AgeMem (Agentic Memory) | RL 训练记忆操作策略 | 训练成本高、可解释性差 |

### 7.4 评测变迁：从 Recall 到 Agentic Utility

这篇综述追踪了 Memory 评测的演进趋势：

| Benchmark | 年份 | 多会话 | Agentic 任务 | 遗忘测试 | 关键发现 |
|-----------|------|--------|-------------|---------|---------|
| LoCoMo | 2024 | ✓ | – | – | RAG 依然远落后人类，尤其时序因果 |
| MemBench | 2025 | – | – | – | 区分事实记忆 vs 反思记忆 |
| MemoryAgentBench | 2025 | – | – | ✓ | 无系统同时掌握 4 项认知能力 |
| MemoryArena | 2026 | ✓ | ✓ | – | LoCoMo 满分模型在此仅 40–60% |

核心结论：**Long context ≠ memory**、**检索质量是瓶颈**、**遗忘评估被严重忽略**、**跨会话一致性仍是开放挑战**。

### 7.5 工程现实与开放挑战

综述花了大量篇幅讨论工程现实——写路径过滤、矛盾处理、延迟预算、隐私治理——以及开放挑战：

- **Continual consolidation**：如何在不灾难遗忘的前提下持续固化
- **Causally grounded retrieval**：通过因果关系而非语义相似度召回
- **Trustworthy reflection**：反思时不能固化错误信念
- **Learned forgetting**：学会安全遗忘过时信息
- **Standardized evaluation**：社区缺乏 GLUE 式的共享评测体系

最后一句值得全文引用：

> **If there is one takeaway from this survey, it is that memory deserves the same level of engineering investment as the LLM itself.** Model selection gets months of careful benchmarking; memory architecture often gets an afternoon. The evidence reviewed here suggests that flipping this priority—treating memory as a first-class system component worthy of dedicated design, testing, and optimization—may be the single highest-leverage intervention available to agent builders today.

## 八、参数化知识：压缩进权重的记忆

前面几节都在讨论"外部状态"（Ledger / Views / Policy），这一节回到记忆的另一极：**参数化知识**。Agent 的 System 1 本身就是一台被预训练压缩过的机器——它知道什么、不知道什么、先验偏向哪里，全都写在权重里。理解参数化知识的压缩原理、注入方式和先验局限，才能理解为什么外部记忆不是"锦上添花"而是"必需"。

### 8.1 参数化知识的本质：以解码器 Transformer 为例

#### 训练原理：把语料分布压进参数

以 GPT 系列为代表的 decoder-only Transformer 是自回归模型。给定 token 序列 $x = (x_1, \dots, x_T)$，联合概率被分解为：

$$

p_\theta(x) = \prod_{t=1}^{T} p_\theta(x_t \mid x_{<t})

$$

训练目标是最大化整个训练语料的对数似然，等价于最小化交叉熵损失：

$$

\mathcal{L}(\theta) = -\frac{1}{T}\sum_{t=1}^{T} \log p_\theta(x_t \mid x_{<t})

$$

其中每一层的计算是残差结构：先做多头注意力（MHA），再做前馈网络（FFN），各自带 LayerNorm 与残差连接。单个注意力头的核心运算是：

$$

\text{Attn}(Q, K, V) = \text{softmax}\!\left(\frac{QK^{\mathsf{T}}}{\sqrt{d_h}}\right) V

$$

$$

Q = XW_Q, \quad K = XW_K, \quad V = XW_V

$$

FFN 则通常是门控结构：

$$

\text{FFN}(x) = W_2 \cdot \sigma(W_1 x)

$$

知识正是通过梯度下降被"写入"这些权重矩阵的。反向传播计算 $\nabla_\theta \mathcal{L}$，优化器（如 AdamW）按 $\theta \leftarrow \theta - \eta \cdot m / \sqrt{v + \epsilon}$ 更新参数。整个过程可以概括为：**语料中的共现统计被压缩进 $W_Q, W_K, W_V, W_O, W_1, W_2$ 与 embedding 矩阵**。

**直观理解 FFN：升维 → 激活 → 降维**。$W_1$ 把隐藏向量从 4096 维升到 11008 维——更大的空间用来"存储和组合特征"；激活函数 $\sigma$（如 GELU）引入非线性，否则两个矩阵相乘仍是线性变换；$W_2$ 再压回 4096 维。例如"苹果"经过 FFN，可能激活第 1024 个神经元（水果相关）、第 5321 个（中国文化相关）、第 8000 个（颜色相关）——这些神经元不是人工指定的，是训练自己学出来的。

**直观理解梯度下降与 AdamW**。假设某参数 $w = 0.35$，反向传播算出 $\partial \mathcal{L}/\partial w = 0.8$，说明增大它会让错误变大，于是 $w \leftarrow 0.35 - 0.01 \times 0.8 = 0.342$（学习率 $\eta=0.01$）。重复"读文本 → 预测 → 算错 → 改参数"几十亿次，知识就编码进去了。AdamW 的两个额外量：$m$ 是一阶矩估计（梯度的移动平均，反映最近趋势），$v$ 是二阶矩估计（梯度平方的平均，反映该参数的变化幅度）——$m/\sqrt{v+\epsilon}$ 让变化剧烈的参数步长自动变小，变化平稳的参数步长自动放大。

#### 分布式表征：知识不落在单个神经元上

训练完成后，一条知识（如"中国的首都是北京"）**并不存在某个具体参数里**。它表现为一组参数的联合激活模式：

- 注意力头负责把"中国""首都"等信息搬运到最后一个 token 的位置；
- MLP 神经元（knowledge neuron）在特定上下文触发时把特征映射到"北京"；
- 一个神经元常常同时参与多条知识的计算（多义性 polysemanticity），一条知识也常常由多个参数共同支撑（叠加 superposition）。

这就是**分布式表征**：知识是参数空间中低维子流形上的激活模式，而不是查表项。它的好处是参数利用率高、泛化能力强；代价是**不可寻址、不可审计**——你无法问模型"你哪几个参数存着'北京是首都'"。

**MLP 神经元是什么**：它是 FFN 中间层的一个标量计算单元 $h_i = \sigma(w_i^{\mathsf{T}} x + b_i)$，可以理解成一个**模糊的特征检测器**——判断当前隐藏表示里"有没有我关心的模式"。每个神经元包含两部分：什么时候触发（由 $W_1$ 中对应行 $w_i$ 决定）和触发后往表示里加什么（由 $W_2$ 中对应列 $v_i$ 决定）。FFN 可展开为 $\text{FFN}(x) = \sum_i h_i v_i$——输入符合某种模式时，就往当前表示里添加某种特征方向。

**多义性（polysemanticity）**：一个神经元可能对多种不相关的上下文都激活。原因是参数有限而潜在特征极多，模型会复用同一组参数表达多个特征——像空间有限的仓库，同一个格子在不同条件下存放不同物品。所以"knowledge neuron"更准确的理解是：**某些知识被计算出来时经常参与其中的一个功能部件**，而不是"这个神经元里存着一条知识"。

**叠加（superposition）**：模型用同一组维度同时编码比神经元数量更多的特征。例如 2 维空间可以放 3 个特征方向 $f_1=(1,0),\ f_2=(0,1),\ f_3=(0.7,0.7)$，某个输入表示 $x = 0.8f_1 + 0.9f_2 + 0.6f_3$ 就是多特征叠加。这提高了参数利用率，但直接后果是：**很难指出某个特征在哪个神经元，改一个神经元会影响多种能力，一条知识不能通过改一个参数安全地删除**。

**Attention 与 MLP 的分工**：Attention 负责"从前文哪些位置取信息并聚合"（把"中国""首都"搬到当前位置），MLP 负责"根据聚合好的表示触发内部学到的特征并改变隐藏状态"（识别国家-首都模式、激活相关知识）。但分工不是绝对的——知识也分布在注意力参数、嵌入层、输出层中。

#### 先验分布：模型即先验

从贝叶斯视角看，训练得到的 $p_\theta$ 是对训练数据分布 $P_{\text{data}}$ 的估计。**模型学到的知识 = 压缩进参数的条件分布**；模型对某个问题的回答，本质上是采样自这个先验：

$$

p_\theta(x_t \mid x_{<t}) \approx P_{\text{data}}(x_t \mid x_{<t})

$$

因此有两个直接推论：

1. **知识截止日期是硬边界**：训练停在哪天，先验就冻结在哪天。2026 年之后发布的行业新规、新产品参数，模型从未见过，先验里就没有它们。
2. **先验顽固（prior stubbornness）**：模型对高频出现的旧模式有很强偏好。注入少量新知识后，模型面对冲突时会"倒向"训练分布中的旧答案——这正是知识编辑与微调困难的根本原因。

### 8.2 参数化知识的注入：四条路径

既然知识在权重里，更新知识就要改权重。按"改动规模从小到大"排列：

#### 路径一：继续预训练（Continual Pre-training / DAPT）

在领域语料上继续跑 8.1 的交叉熵损失。数学形式完全相同，只是数据换成垂直领域文本（如金融公告、法律文书）。原理是**继续移动先验**：让 $P_{\text{data}}$ 从通用语料迁移到目标分布。

优点：知识密度高时效果好（如"持续预训练让金融模型认识财报术语"）。
缺点：

- **灾难性遗忘（catastrophic forgetting）**：新语料覆盖旧知识，通用能力倒退；
- **成本高**：需要与预训练同量级的算力，且学习率必须压得很低；
- **知识穿越（knowledge traversal）**：每次前向都要穿过全部参数，为读一条知识付出全模型计算。

缓解遗忘的常见做法是在损失里混合旧语料（replay）或加正则项，如 EWC：

$$

\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{new}} + \frac{\lambda}{2}\sum_i F_i (\theta_i - \theta_i^{*})^2

$$

其中 $F_i$ 是 Fisher 信息矩阵对角元，惩罚偏离旧参数的行为。

**直观理解 EWC**：把 $\theta_i$ 看作第 $i$ 个参数的当前值，$\theta_i^{*}$ 是旧任务训练完成时的原值，$(\theta_i - \theta_i^{*})^2$ 就是"参数偏离了多远"（平方让正负偏离同价、大幅偏离受更重惩罚）。$F_i$ 衡量这个参数对旧任务有多重要——**$F_i$ 大的参数像承重墙，动一点旧能力就塌；$F_i$ 小的参数像家具，可以随意挪**。$\lambda$ 控制保护力度：太大学不进新知识，太小旧知识崩塌（稳定性-可塑性困境）。注意 EWC 只考虑单个参数的重要性（Fisher 对角元），忽略参数间的组合关系，而知识是分布式的，所以它只是近似保护，工程上常与 replay、LoRA 组合使用。

#### 路径二：监督微调（SFT）

在指令-回答对 $(x, y)$ 上继续优化交叉熵：

$$

\mathcal{L}_{\text{SFT}} = -\frac{1}{|y|}\sum_{t} \log p_\theta(y_t \mid x, y_{<t})

$$

**训练细节（Teacher Forcing）**：预测回答的第 $t$ 个 token 时，模型看到的是标准答案中真实的正确前文（而不是自己可能生成错的内容）——这让训练稳定、可并行，但推理时前文是模型自生成的，可能已经出错，形成训练/推理差异。

**loss mask**：聊天模型通常只对 assistant 回答部分计算损失，用户指令和系统提示的 token 标记为忽略（如 -100），让模型主要学习 $p_\theta(\text{标准回答} \mid \text{指令})$。

原理：SFT 主要调整**行为分布**（学会回答问题、遵循格式），而不是**事实知识**——它学到的是数据中反复出现的行为模式：看到"请逐步解释"就分步回答，看到"只返回 JSON"就输出 JSON。当数据里重复出现"（问题，新事实答案）"时，它也能写入一些新知识，但效率远低于预训练——因为梯度信号只在回答位置回传，且容易把"新知识"记住成"格式套路"。

#### 路径三：局部知识编辑（Knowledge Editing）

典型代表是 ROME（Rank-One Model Editing）与 MEMIT。前面 8.1 说过模型整体是"黑盒"——1750 亿参数无法逐一看懂。但**数学上它不过是一堆矩阵 $W_1, W_2, W_Q, W_K, W_V, \dots$ 的复合**。知识编辑的思路是：既然知识分布在这些矩阵里，而某些事实的关联集中落在少数 FFN 层上，那就**定位到那一层，只改那一小块**。

知识编辑发展至今，主流方法收敛为三大类：**先定位、后编辑（locate-then-edit）**、**元学习与超网络（meta-learning / hypernetwork）**、**适配器或外挂模块（adapter / plug-in module）**。三类的共同点是都不重训全模型，区别在于"改动落在哪里"。

**第一类：先定位，后编辑——LAMA 探针、因果追踪与 ROME / MEMIT**

这一类的前提是**先证明并定位"知识在参数里"**，靠两件工具完成：

**LAMA 探针（Language Model Analysis）**：用填空式提示（cloze）探测模型知道什么——把事实写成"法国的首都是 [MASK]"让模型填空，看概率最高的答案是不是"巴黎"。LAMA 在 GPT、BERT 等模型上测出：**无监督预训练的语言模型确实记住了大量事实**（在部分关系上甚至超过监督基线）。它的价值不是"定位到神经元"，而是**确证了知识以可探测的形式存在于参数中**——为"去参数里改知识"提供了合法性。

**因果追踪（causal tracing）**：跑一遍"巴黎 → 法国首都"这类事实，把主体 token 的隐藏状态加入噪声破坏，再逐层、逐位置地还原某个中间激活，观察哪一层还原后答案恢复——哪个位置对答案影响最大，哪里的事实关联就最集中。实验发现：**事实关联主要集中在中间若干 FFN 层（如 GPT-J 的第 5–7 层附近），而不是均匀分布在全模型**。

定位完成后的**改写**是一个约束优化问题。把第 $l$ 层 FFN 的输出矩阵记作 $W_0$，主体位置输入该层前的隐藏状态为 $h$，则这条事实的"键"为 $k^* = W_0 h$，期望的答案方向记作 $v^*$。要"把这条知识的输出从旧值拧到 $v^*$"，同时**不改变其他所有关联**：

$$

\min_{W} \| W k^* - v^* \|^2 \quad \text{s.t.} \quad W k_i = v_i,\; \forall i

$$

约束 $W k_i = v_i$ 保护其他事实的键值映射不被破坏。用拉格朗日乘子解出闭式解，得到 ROME 的**秩一（rank-1）修正**：

$$

\Delta = \frac{(v^* - W_0 k^*)\, (C^{-1} k^*)^{\mathsf{T}}}{(C^{-1} k^*)^{\mathsf{T}} k^*}, \qquad W_1 = W_0 + \Delta

$$

其中 $C = \sum_i k_i k_i^{\mathsf{T}}$ 是一段语料上所有键的外积和（未中心化协方差矩阵），作用是**把修正方向按数据分布重新归一化**——只动与事实入口对齐的方向，避免误伤其他知识。$\Delta$ 是两个向量的外积，秩为 1，所以叫"秩一编辑"。

**MEMIT（Mass-Editing Memory in a Transformer）**把秩一推广到**批量**：一次要改 $N$ 条事实时，把 $N$ 个键、$N$ 个值分别堆成矩阵 $K, V \in \mathbb{R}^{N \times d}$，并把改动**分散到连续多层**（残差流是相加的，每层只承担一部分修正，逐层叠加后恰好凑出总改动），闭式解是带岭回归（ridge）的形式：

$$

\Delta = (V - W_0 K)\, K^{\mathsf{T}} (K K^{\mathsf{T}} + \lambda I)^{-1}

$$

$\lambda$ 控制"新事实写得多用力"与"旧参数动多少"的权衡。$\Delta$ 的秩至多 $N$（远小于维度 $d$），仍是低秩更新——**编辑条数越多，需要的秩越高，这正是 MEMIT 能批量编辑数千条而不崩、但继续编辑上万条仍会退化的原因**。

**验证（Verify）**：检查新事实生效（"巴黎的首都是 X"答对），且邻近事实不受影响（"法国首都是 X"也应正确，而非被误伤）。

**为什么可行**：虽然知识是分布式的（8.1），但**单个事实在计算路径上的"入口"往往是局部的**——某层的某几个神经元承担了"识别（主体, 关系）并触发答案"的角色。改这一小块，等于给这条知识换了个出口，而其他知识因为走不同的入口而几乎不受影响。

优点：**单条知识秒级更新、不改变其他行为**。缺点：

- **涟漪效应（ripple effect）**：改一条事实可能波及相关推理（一个神经元参与多条知识，8.1 的多义性）；
- **规模化后遗忘**：连续编辑成百上千条后，模型出现渐进遗忘甚至灾难性遗忘（见下节"持续学习"）；
- **知识定位不总是准确**：并非所有知识都干净地落在一个 MLP 层里（叠加与多义性让某些事实的入口分散在多层）；
- **依赖语料估计**：$C$ 来自抽样语料，语料分布偏差会传导到编辑质量。

**第二类：元学习与超网络——学会"怎么改"**

先定位后编辑把"改哪里"当作分析问题；元学习一派则把"改"本身当作**可学习的技能**——训练一个编辑网络，让它见到一条新事实就输出对应的参数修改。

**KnowledgeEditor（De Cao et al.，2021）**是超网络（hypernetwork）思路的开端：一个辅助网络 $H_\phi$ 把待编辑事实的表示（主体、关系、对象三者的 embedding）映射成对主模型参数的修改量：

$$

\theta' = \theta + \Delta\theta, \qquad \Delta\theta = H_\phi(e_{\text{subj}},\, e_{\text{rel}},\, e_{\text{obj}})

$$

训练目标分两半：**编辑损失**让 $\theta'$ 在新事实上答对，**约束损失**让 $\theta'$ 在未编辑的邻近样本上与原模型行为一致——只学会"这一个事实的修改"，不影响邻居。

**MEND（Model Editor Networks with Gradient Decomposition）**解决了超网络的规模问题：直接输出全量 $\Delta\theta$ 对千亿参数不可行，于是**以"梯度"为输入、以"低秩因子"为中间表示**。对某层权重 $W$，先计算单条编辑样本的梯度 $g = \nabla_W \mathcal{L}$，做奇异值分解得到一组秩一因子，再用小网络重组：

$$

g = \sum_i \sigma_i\, u_i v_i^{\mathsf{T}} \;\Longrightarrow\; \Delta W \approx \mathcal{E}_\theta\big(\{(\sigma_i, u_i, v_i)\}\big) = \sum_{i=1}^{r} h(\sigma_i, u_i, v_i)

$$

其中 $h$ 是一个跨层共享的小 MLP（以层号做条件）。把"分解 → 小网络重组合"而不是"直接学整个梯度矩阵"，参数量从 $O(d^2)$ 降到 $O(r(d+1))$——这让 MEND 能把编辑器训练到 GPT-J、GPT-NeoX（几十亿参数）规模。训练方式是**元学习**：在大规模"随机事实对（旧事实→新事实）"上做双层优化——内层应用编辑、外层优化 $\mathcal{E}_\theta$ 使编辑后的模型在新事实上损失最小。同类工作还有 MEGA（Massive Editing via Meta Learning）：在元学习目标里显式加入任务级损失，让编辑网络面对数千条连续编辑时依然稳定。

**第三类：适配器或外挂模块——不动原模型，在旁边"搭架子"**

这一类最保守也最工程化：**原模型参数完全不改**，编辑效果通过额外的小模块、附加向量或旁路模型实现。三个代表：

**Transformer-Patcher（一个错误补一个神经元）**：冻结所有原参数，每次编辑在最后一层 FFN 上**新增一个神经元**（patch），并训练一个门控让它**只在遇到被编辑的样本时才激活**。原知识由原神经元承载，新知识由补丁神经元承载，二者物理隔离——连续编辑几百条不互相干扰，且天然可解释（哪个 patch 对应哪次编辑一目了然）。

**GRACE（Lifelong Model Editing with Discrete Key-Value Adaptors）**：名字里的"Key-Value Adaptors"点明了机制——为每条编辑存一对向量：**director**（注入中间层表示，把信息流引向被编辑的知识）和 **chaperone**（在最后一层注入，放大期望输出）。推理时用表示相似度判断当前输入是否命中某条编辑，命中就把这对向量加进前向计算。**不碰权重、可无限追加**，代价是编辑多了之后命中判断变模糊。

**SERAC（Memory-Based Model Editing at Scale）**：把"外挂"做到最彻底——训练两个小东西：一个**范围分类器**（scope classifier，判断当前输入是否落在某条编辑的作用范围内）和一个**反事实模型**（counterfactual model，一个在编辑样本上微调过的小模型）。推理时：分类器判为"范围内"→ 用小模型回答；"范围外"→ 用原模型回答。原模型自始至终**零改动**，编辑 = 往记忆库里加样本 + 更新小模型。

三类方法对照：

| 类别 | 代表 | 改动位置 | 单条成本 | 可解释性 | 主要风险 |
|------|------|---------|---------|---------|---------|
| 先定位后编辑 | LAMA + ROME / MEMIT | 特定层 MLP 权重 | 极低（秒级） | 中（需因果分析） | 批量编辑的渐进遗忘 |
| 元学习/超网络 | KnowledgeEditor / MEND | 全权重（由网络生成 $\Delta\theta$） | 低 | 低（黑盒生成修改） | 编辑网络训练成本、跨模型迁移差 |
| 适配器/外挂 | Transformer-Patcher / GRACE / SERAC | 原权重之外 | 低 | 高（模块即记录） | 编辑多了命中退化、外挂体积增长 |

一句话：**先定位后编辑"精准但脆"，元学习"通用但黑"，外挂模块"稳妥但笨"**——工业界常按"编辑量、可解释性要求、模型规模"三者取舍，也可以混用（如先外挂兜底，再定期把高频编辑固化进参数）。

#### 路径四：参数高效微调（PEFT，如 LoRA）

LoRA 的核心假设：**模型微调时的参数变化 $\Delta W$ 是低秩的**。于是不直接改 $W_0$，而是引入两个小矩阵 $B \in \mathbb{R}^{d \times r}$、$A \in \mathbb{R}^{r \times k}$（$r \ll \min(d,k)$）：

$$

W' = W_0 + \Delta W = W_0 + BA

$$

训练时冻结 $W_0$，只优化 $A, B$。推理时可以合并回 $W_0 + BA$，零额外延迟；也可以把不同任务的 LoRA 插拔式切换，互不干扰。

数学原理：低秩分解把可训练参数量从 $d \times k$ 降到 $r(d+k)$（例如 4096×4096 矩阵配 $r=16$，参数量降到原来的 1/256）。

**为什么低秩就够用——奇异值谱的直观解释**：任何矩阵可分解为 $W = U\Sigma V^{\mathsf{T}}$，$\Sigma$ 对角线上的奇异值从大到小排列。"奇异值谱高度倾斜"指**前几个奇异值极大、后面的快速衰减趋近于 0**——矩阵的主要信息集中在前几个方向上。直觉类比：$W_0$ 像一座已经建好的城市，主干道（大奇异值方向）承载着模型的主能力（语言、推理），微调不需要重铺路，只需在旁边修几条小路（低秩 $\Delta W = BA$）就能到达新任务的目的地；反之若奇异值谱是"平的"（所有方向能量相当），低秩近似就会失效，必须全参数微调。这正是 LoRA 取 $r = 8 \sim 16$ 就足够、而秩再大收益甚微的原因。

**注入方式的取舍对照**：

| 路径 | 改动对象 | 单条知识成本 | 通用能力保持 | 时效性 |
|------|---------|------------|------------|--------|
| 继续预训练 | 全部权重 | 极高 | 中（需 replay） | 好 |
| SFT | 全部权重 | 中 | 中 | 中 |
| 知识编辑 | 单个 MLP 层 | 极低 | 好（但批量会退化） | 好 |
| LoRA | 低秩增量 | 低 | 好 | 中（需按任务切换） |

#### 持续学习（Continual Learning）：参数化记忆的连续写入与灾难性遗忘

8.2 的四条路径回答"怎么把新知识写进权重"，持续学习回答更根本的问题：**模型要连续学习多个任务、多批知识，怎么保证学新不忘旧**。形式化地说，模型依次在任务 $T_1, T_2, \dots, T_n$ 上学习，每学完一个任务都要尽量保持之前所有任务的性能：

$$

\min_{\theta}\; \sum_{i \le t} \mathbb{E}_{(x,y)\sim D_i}\big[ \mathcal{L}(f_\theta(x), y) \big]

$$

**灾难性遗忘（catastrophic forgetting）**：当 $f_\theta$ 是共享参数的神经网络时，直接在新任务上继续训练，梯度更新会覆盖对旧任务重要的权重方向，旧任务性能断崖式下跌（McCloskey & Cohen, 1989；French, 1999）。原因在 8.1 已埋下伏笔：**知识是分布式表征**——同一组参数同时编码新旧知识，改参数服务新知识时，旧知识没有独立的"存档位"，自然被挤掉。对 LLM 而言，灾难性遗忘意味着：继续预训练金融语料后通用能力悄悄退化；SFT 新格式后旧指令跟随能力下降。

缓解灾难性遗忘的三大主线，恰好与 8.2 的四条路径一一呼应：

**主线一：正则化（regularization）——约束参数别走远**。在损失里加"偏离旧参数"的惩罚，典型是 8.2 路径一里讲过的 EWC（承重墙比喻：Fisher 信息大的参数不许动），以及 SI、LwF（用旧模型输出做蒸馏约束）。思想：**旧知识不许被大幅改写，只允许小幅挪动**。

**主线二：参数隔离（parameter isolation）——给每个任务划出专属参数**。核心是**用掩码或分块把参数空间切成互不重叠的子集**，任务 $t$ 只更新自己的子集：

$$

\theta^{(t)} = m_t \odot \theta, \qquad m_t \in \{0,1\}^{|\theta|}, \quad m_i \cap m_j = \varnothing

$$

PackNet 的做法是"训练 → 剪枝 → 冻结"：先训好一个子网，把不重要的权重剪掉并冻结，为下一个任务腾出参数；渐进网络（Progressive Networks）则给每个任务新开一列参数，用横向连接复用旧任务的特征。参数隔离的代价是**容量随任务数增长**——这正是 LoRA（8.2 路径四）和"每个任务一个适配器"能在 LLM 上落地的深层原因：**低秩增量本身就是一种参数隔离**（每个任务的 $A_t, B_t$ 互不相干，插拔切换天然免疫遗忘）。

**主线三：记忆回放（memory replay）——把旧任务的数据"带回来"重学**。训练新任务时混入旧任务样本（经验回放 Experience Replay）：从回放缓冲 $\mathcal{B}$ 采样旧样本一起算损失：

$$

\min_{\theta}\; \mathcal{L}_t(\theta) + \beta \sum_{(x,y)\in \mathcal{B}} \mathcal{L}\big(f_\theta(x), y\big)

$$

iCaRL 用"每个类保留代表性样本"做回放，实现类增量学习；A-GEM 更进一步——**不直接回放样本，而是把新任务的梯度投影到"不会增大旧任务损失"的方向**：

$$

\min_{g} \| g - g_{\text{new}} \|^2 \quad \text{s.t.} \quad g^{\mathsf{T}} g_{\text{old}} \ge 0

$$

即只允许"与旧任务梯度方向一致"的更新，一阶近似地保证每一步都不伤害旧任务。生成式回放（generative replay / pseudo-rehearsal）则训练一个生成器，用"模拟的旧数据"代替真实样本。

**与本文的联系**：三条主线在 Agent Memory 里都有投影——正则化对应 EWC 类约束微调；参数隔离对应多任务 LoRA 与 8.2 的"外挂模块"（模块互不相干 = 天然隔离）；记忆回放对应**把旧知识存进外部记忆、训练或推理时再注入**——本质是把"参数里的旧知识"换成"外部可重放的旧知识"，这也是第三节"非参数化 Memory"能缓解参数化遗忘的原因。工程上三者常组合使用：**重放保底、隔离保稳、正则化保精度**。

### 8.3 先验分布的缓解：三个侧面

先验顽固是参数化记忆的"阿喀琉斯之踵"，缓解手段分三个侧面：

#### 训练侧：移动先验

直接改变 $P_{\text{data}}$，让新知识成为高频。手段包括继续预训练、领域数据混合、数据重加权、课程学习。这是唯一能**真正改写先验**的方式，但成本最高、最慢，且永远追不上知识产生的速度。

#### 推理侧：条件覆盖先验

不改权重，在推理时把新知识放进上下文，让条件概率被证据主导：

$$

p_\theta(x_t \mid x_{<t}, \text{evidence})

$$

即 RAG / 上下文注入。这是当前工业界缓解知识滞后的主力手段——新知识只要写进检索库即可生效，零训练成本。缺点是：上下文窗口有限、检索质量决定上限（"趋近而非有用"）、长上下文存在 lost in the middle 现象。解码侧还可以用上下文感知解码（context-aware decoding），在采样时压制与证据冲突的先验 token。

上下文感知解码只是"干预模型决策"的第一步。按干预位置的不同，这类手段可分为三层：

**解码层干预：上下文感知解码（CAD, Context-Aware Decoding）**。推理时同时算两路 logits：带证据 $c$ 的 $p_\theta(y \mid x, c)$ 和不带证据的 $p_\theta(y \mid x)$，采样时用对比式解码**放大二者的差异**：

$$

\log p_{\text{CAD}}(y_t) = (1+\alpha)\, \log p_\theta(y_t \mid x, c) \;-\; \alpha\, \log p_\theta(y_t \mid x), \quad \alpha \in [0,1]

$$

直觉：某 token 只在有证据时才被模型看好（$p_\theta(\cdot \mid c)$ 显著大于 $p_\theta(\cdot)$），说明它由证据支撑，$\alpha$ 越大越被放大；反之若模型"不靠证据也想说"，说明是参数先验在发声，会被压制——**相当于在 softmax 之前对先验做了一次显式的"减刑"**。代价：$\alpha$ 过大时，证据里没有的一般知识（"法国的首都在哪"这类与检索段落无关的常识）也会被误伤，所以出现了动态 CAD（按上下文不确定性自适应调整 $\alpha$）。

**证据层干预：FaithfulRAG（fact-level conflict modeling）**。CAD 的问题在于"无差别压制先验"——它并不判断上下文和先验谁对。FaithfulRAG 的观察是：先验与证据冲突时，模型会犯两类错——**过度自信错**（无视上下文、死守参数知识）和**错误匹配错**（无脑倒向检索段落，哪怕段落本身是误导的）；强行用提示词或对比解码追求"忠实"，只是把第一类错误转嫁成第二类。它的做法是在**事实粒度（fact-level）显式建模冲突**：先让 LLM 做"自我事实挖掘"（self-fact mining）——把参数知识中与问题相关的事实抽出来（self-facts）；再把 self-facts 与检索上下文逐段对齐，找出**冲突事实**；最后用一个"自思考"（self-thinking）模块让模型**先推理、后生成**——针对每个冲突点想清楚采信哪边、为什么，再作答。即：**不替模型做决定，而是把冲突摆到明面上让模型自己裁决**。

**记忆层干预：RMM（Reflective Memory Management）**。干预点再往前一步——连"哪些记忆进入上下文"都由反射机制动态决定。RMM 为每条记忆维护"它未来为什么有用"的**前瞻理由**（prospective rationale），检索后先用可学习的重排器 $g_\phi$ 排序；生成回答后进入**回顾反思**（retrospective reflection）：对每条被用到的记忆生成"它到底帮没帮上忙"的回顾理由，再以 LLM-as-judge 的评判为奖励，**用强化学习更新重排器 $g_\phi$**——下次遇到类似查询，真正派得上用场的记忆会被排得更靠前。三层干预的共性：**都不改权重，只在推理路径上"拧"决策分布**——这正是推理侧（而非训练侧、后验侧）干预的题中之义。

#### 后验侧：对后验做手术

介于两者之间：不动整体训练，直接修正后验分布的关键位置。知识编辑（8.2 路径三）就是在后验上做局部手术；LoRA 切换则可以理解为"把多个后验版本并存，按任务选择"。后验侧手段快、准，但规模化后的可靠性仍是开放问题。

**一个关键认识**：三个侧面不是互斥的，而是按"知识的使用频率与时效性"分工——高频稳定知识走训练侧写进先验；中频时效知识走后验侧；低频、易变、高保真需求的知识走推理侧注入。

### 8.4 基于读写效率的记忆分层：Memory3 的形式化

这一小节的数学与原理来自《记忆工程》参考文献 [1]（即 [Memory3 论文](https://arxiv.org/abs/2407.01178)，arXiv:2407.01178，[PDF](/papers/memory3-explicit-memory.pdf)）。它给出一个非常干净的观察：**知识应该存在哪种记忆格式，取决于读写成本与使用频率的权衡**。

把 LLM 的一生看作"把知识从原始数据搬运到计算"的过程，总成本写作：

$$

\sum_{\text{knowledge } k} \min_{\text{format } m} \Big[ \text{cost}_{\text{write}}(k, m) + n_k \cdot \text{cost}_{\text{read}}(k, m) \Big]

$$

其中 $\text{cost}_{\text{write}}$ 是把知识 $k$ 编码进格式 $m$ 的成本，$\text{cost}_{\text{read}}$ 是推理时把 $k$ 从格式 $m$ 读入计算的成本，$n_k$ 是这条知识在模型生命周期内的期望使用次数。

Memory3 用 2.4B 模型实测了三种格式的 TFlops 成本（详见附录 A 的推导）：

$$

\begin{cases}
c_{\text{implicit}}(n) \ge 2.24 & \text{（模型参数）}\\
c_{\text{explicit}}(n) = 0.308 + 0.000144\, n & \text{（显式记忆）}\\
c_{\text{external}}(n) \ge 0.624\, n & \text{（RAG 纯文本）}
\end{cases}

$$

解读：

- **模型参数（implicit）**：写入 = 训练（约 2.24 TFlops/条），读取 ≈ 0（矩阵乘法顺带完成）。参数每次前向都被遍历，读成本与使用次数无关；
- **RAG 文本（external）**：写入 = 0（存文本不花钱），读取 = 每次都要重新编码并塞进上下文（约 0.624 TFlops/次），用得越多次越贵；
- **显式记忆（explicit）**：写入一次约 0.308 TFlops，读取极便宜（约 $1.44 \times 10^{-4}$ TFlops/次）。

由此得到**记忆分层**：plain text (RAG) → explicit memory → model parameters，越往上写成本越高、读成本越低。对单条知识，选择使总成本最小的格式。令三种成本曲线两两相交，得到显式记忆的最优区间：

$$

n \in (0.494,\ 13400)

$$

即：**一条知识若在一生中被使用约 0.5 次到 1.34 万次之间，显式记忆是最优解**——用得极少就放 RAG（写零成本），用得极多就固化进参数（读零成本），中间地带全部交给显式记忆。

这套分层与人类记忆高度同构：常见表达（implicit，肌肉记忆式随取随用）、读过的书（explicit，需要时回忆）、开卷考试翻资料（external，现查现用）。

### 8.5 基于注意力键值对的显式记忆：训练与推理

先记住一句话核心：

> **Memory3 不是把参考资料塞进上下文，也不是把知识训练进参数，而是提前把参考资料编码成注意力层可直接读取的 K、V 向量；推理时检索相关资料，把 K、V 插进注意力计算。** 它相当于一份"持久化、压缩过的 KV Cache"。

#### 先理解：KV head 是什么

注意力机制里，Q、K、V 各司其职：

- **Q（Query）**：我现在要找什么？
- **K（Key）**：我这里是什么信息，什么时候该匹配我？（索引、标签）
- **V（Value）**：匹配到我后，我提供什么内容？（实际内容）

一个 KV head 就是"一套索引 + 内容表示"。Memory3 使用 GQA（分组查询注意力）：**40 个 Query head 共享 8 个 KV head**（每 5 个提问者共用一套资料）。为什么不减 Q 而减 KV？因为推理时要缓存所有历史 token 的 K、V（KV Cache 大小正比于 $N_{KV}$），从 40 减到 8 让缓存缩小到原来的 1/5；而 Query 只作用于当前 token，不需要长期缓存。注意：**一个 KV head 不是一条知识**，它只是一套投影空间，任何 token 经过它都会产生 K、V——知识仍然是分布式的。

#### 写入（记忆编码）：把参考文本变成 KV

把参考文本（≤128 token）独立送进模型前向编码——**不是训练，没有反向传播**——每一层、每个 KV head、每个 token 都会生成自己的 K、V，然后从中摘取最有信息量的部分存下来：

- **层稀疏**：44 层只取前 22 层（middle layers 更接近任务输出，后层不必外置）；
- **头稀疏**：8 个 KV head 全部作为 memory heads（GQA 已把 KV 从 40 减到 8，这一维不再压缩）；
- **token 稀疏**：每层每 head 从 128 个 token 中选 top-8。token 重要性 = 它收到的注意力之和：

$$

w_j^{l,h} = \sum_{i=0}^{127} \tilde{a}_{i,j}^{l,h}

$$

被关注越多的 token（如"中国""首都""北京"）越重要，虚词被舍弃。不同层、不同 head 可以选不同 token；

- **维度压缩**：向量量化（OPQ20x80-Residual2x14-PQ8x10）把 80 维 bf16 压到 14 维 uint8，约 11.4 倍（有损，但评测显示影响可忽略）。

最终一条记忆的形状是 $(22,\ 2,\ 8,\ 8,\ 80)$（memory layers, K/V, KV heads, sparse tokens, head dim）——约 440 KiB。整体稀疏度 160x（不加量化）到 1830x（加量化），记忆库从 7.17 PB 压到 45.9 TB 或 4.02 TB，可放进 GPU 集群磁盘。

#### 读取（推理注入）：KV 拼接进注意力

推理时做**两级检索**：

1. **粗检索**：每生成 64 个 token，用当前片段经 BGE-M3 嵌入 + FAISS 做向量检索，从记忆库找出 5 条相关参考文本（类比：从整个图书馆找出 5 本相关书）；
2. **细读取**：取出这 5 条文本预存的 K、V，拼接到当前自注意力的 KV 序列上，让模型用 Query 与记忆 Key 匹配、读取记忆 Value（类比：从 5 本书中选当前真正需要的具体内容）。

公式本质很简单——只是把注意力的 K、V 从"只有上下文"换成"上下文 + 记忆"：

$$

K_{\text{all}} = \text{concat}(K_0, \dots, K_4,\ K_{\text{context}}), \quad V_{\text{all}} = \text{concat}(V_0, \dots, V_4,\ V_{\text{context}})

$$

$$

Y_i = \text{softmax}\!\left( \frac{q_i K_{\text{all}}^{\mathsf{T}}}{\sqrt{d_h}} \right) V_{\text{all}}

$$

即：**当前 token 不仅能关注前面的对话，还能直接关注检索出来的记忆**。

两个工程细节：

- **并行位置编码**：5 条记忆各自使用相同的 0~127 位置区间，像并排摆放的资料，而不是串行排队——避免排在第 5 条的记忆因位置偏远被弱化（lost in the middle）；
- **RoPE 后稀疏化**：先给 Key 注入位置信息（如"北京"在第 12 位），再选 top-8 token，被选中的 token 保留原始相对位置——若先删 token 再重新编号，相对关系就破坏了。

#### 为什么是高保真映射

这是显式记忆与参数化记忆的本质区别：

- **参数化记忆**是**有损压缩**——知识编码进分布式权重后，细节丢失、不可审计、先验固化；
- **显式记忆**是**无损引用**——KV 直接来自参考文本编码，与原文一一对应（key 决定"何时被想起"，value 决定"想起什么"）。答案可以从记忆中高保真地"抄"出来，而不是从先验里"猜"出来。

评测印证：Memory3-SFT（2.4B）在 HaluEval / TruthfulQA / HalluQA 上平均 48.60 分，超过 Phi-2（38.31）、Gemma-2B（38.04），甚至超过 Falcon-40B（35.37）。

#### 训练：两阶段预训练

Memory3 预训练分两段：

1. **Warmup 阶段**：普通预训练，不注入记忆。直接带显式记忆从头训练会让模型学会"忽略记忆"（模型太弱时无法理解自己生成的记忆，注意力层会学成无视它们）；
2. **Continual train 阶段**：在训练序列前拼接检索到的参考（每序列 32 chunk × 128 token = 4096 参考 token），实时编码成显式记忆参与自注意力。为防止泄漏，要求训练序列与参考的重叠 < 90%。

两阶段让模型学会"写记忆"和"读记忆"，具体知识本身大多外置——这正是 8.4 分层思想在训练目标上的体现：**让参数只学抽象知识，让具体知识留在记忆库里**。全程不增加任何新参数（直接复用 $W_Q, W_K, W_V, W_O$）。

#### 行业落地的意义

在专业任务（法律 JEC-QA、医学 C-Eval/MMLU）上，Memory3 验证了一个关键特性：**适配新领域只需往知识库里导入该领域的参考文本**（法规、医学书籍），把参考转成显式记忆即可推理，**完全不需要微调**。对比参数化路径（8.2 的四条路径都要动权重、承担遗忘与成本），这是"知识更新频率与成本"问题的一个结构性答案。

### 8.6 显式记忆：组织形式、状态机与 MemGPT 分页

8.4 与 8.5 分别从"读写成本"和"注意力 KV 形态"两个角度展示了显式记忆（explicit memory）——**存在权重之外、以可寻址形式组织、推理时按需读入**的记忆。这一节把它作为一等公民展开：它有哪些典型组织形式，为什么它能把大模型从"无状态函数"变成"有状态状态机"，它与冻结的权重如何解耦，MemGPT 又如何用操作系统的分页思想管理它。

#### 显式记忆的典型组织形式

显式记忆的"存储格式"决定了读写成本与检索方式，主流组织形态有五种：

| 形态 | 存储单元 | 写入方式 | 读取方式 | 代表 |
|------|---------|---------|---------|------|
| 纯文本库 | 文档/段落 | 直接落盘（零成本） | 检索后塞进上下文 | RAG、向量库 |
| 结构化记录 | 原子记忆单元（9.3） | 抽取 + 规范化 + 落库 | SQL/键值点查 | Mem0、PowerMem |
| 知识图谱 | 实体-关系三元组 | 抽取 + 建边（可带时间戳） | 图遍历、多跳推理 | Graphiti、Neo4j |
| 分层摘要 | 摘要树 | 滚动摘要、递归合并 | 按粒度逐级下钻 | RAPTOR、滚动摘要 |
| 注意力 KV 形态 | 稀疏 K/V 向量 | 前向编码 + 剪枝（8.5） | 直接拼进注意力 | Memory3 |

一条共性规律：**越"结构化"的形态，写入成本越高、读取越精确**。纯文本写零成本但每次读取都要重新编码（8.4 的成本公式）；KV 形态写入时编码一次、读取时近乎零成本地参与注意力。显式记忆的设计空间，就是在这条读写成本曲线上选位置。

#### 从无状态函数到有状态状态机

没有显式记忆的 LLM 是一个**无状态函数**：$y = f_\theta(x)$，同样的输入永远得到同样的输出（给定解码参数），它不记得上一轮说过什么，也没有"内部状态"——每次调用都是冷启动。

接上显式记忆 $M$ 和两个算子（读 $\mathcal{R}$、写/管 $\mathcal{U}$）之后，整个系统变成一个**有状态的状态机**：

$$

s_{t+1} = \mathcal{U}\big(s_t,\; o_t\big), \qquad y_{t+1} = \pi_\theta\big(x_{t+1},\; \mathcal{R}(s_t, q)\big)

$$

其中状态 $s_t = (M_t,\, c_t)$ 由记忆库 $M_t$ 与当前上下文 $c_t$ 组成，$o_t$ 是环境反馈。**LLM 不再是那个函数，而是状态机里的转移函数 $\pi_\theta$**：读记忆 → 决策 → 写记忆 → 状态更新，循环往复（正是 7.1 的 Write-Manage-Read 闭环）。系统的记忆由三层共同构成，恰好对应 9.9 的载体划分：

- **瞬时状态**：隐藏状态（每步计算中的中间表示，见 9.9）——状态机的"寄存器"；
- **会话状态**：上下文 + KV Cache——状态机的"内存"，随对话推进增长；
- **持久状态**：显式记忆库 $M_t$——状态机的"磁盘"，跨会话存活。

三者区别在于生命周期与可寻址性：寄存器随计算消失，内存随会话释放，磁盘显式可查、可改、可回放。**状态机的价值**：同样的输入在不同状态下会得到不同输出——"记得昨天说过的偏好"改变今天的回答，这正是 Agent 区别于纯 API 调用的本质。

#### 解耦冻结的参数化记忆

"怎么将被冻结的参数化记忆解耦"——这句话拆开是两层：

1. **冻结**：主模型 $\theta$ 不再参与任何梯度更新（零训练成本、零遗忘风险）；
2. **解耦**：本该由权重承载的知识，改由外部显式记忆承载；权重只保留"能力"——语言能力 + **读写记忆的能力**（检索、注入、评估）。

解耦后的分工变成：**权重回答"怎么想"（如何组织语言、如何推理、如何评估证据），显式记忆回答"知道什么"（事实、偏好、历史）**。这带来三个结构性收益：

- **遗忘消失**：知识更新 = 更新记忆库，不是改写权重，不存在"新旧知识抢参数"（对比 8.2 的持续学习困境）；
- **可寻址、可审计**：每条知识是库里的一个可查记录（9.15 的溯源链），而不是分布式权重里不可指认的激活模式；
- **能力与知识分离**：换一批知识库 = 换一个专业领域，模型本体不动——8.5 里 Memory3 导入法律/医学语料即用、零微调，就是解耦的直接演示。

工程上"解耦"的具体形态有三档：**RAG 档**（知识以文本存库，检索后注入上下文）、**KV 档**（Memory3，知识以注意力 K/V 形态存在，直接参与计算）、**工具档**（MemGPT/AgeMem，冻结模型通过函数调用读写记忆，见下）。

#### MemGPT：类操作系统的分页机制

MemGPT（[MemGPT: Towards LLMs as Operating Systems](https://arxiv.org/abs/2310.08560)，arXiv:2310.08560）把"LLM + 显式记忆"整体建模成**一台计算机**，操作系统比喻几乎逐条对应：

| 操作系统 | MemGPT | 说明 |
|---------|--------|------|
| 物理内存（RAM） | 主上下文（main context） | LLM 每一刻"看得见"的内容，含系统提示中的核心记忆槽位（人设、用户画像、工具说明等） |
| 磁盘（disk） | 档案存储（archival storage） | 无限增长的持久记忆，平时不在上下文里 |
| 内存管理单元/分页 | 记忆管理器（memory manager） | 由 LLM 自己通过函数调用（read / write / append / search）执行 |
| 缺页中断（page fault） | 上下文溢出（context overflow） | 上下文快满时触发，LLM 被要求"腾地方" |
| 换出（swap out） | 逐出 + 递归摘要 | 把最旧的消息压缩成摘要，写回档案存储 |
| 换入（swap in） | 检索加载 | 需要时按查询把相关档案检索回主上下文 |

**分页循环**：上下文使用量逼近上限 → 触发 self-editing（LLM 调用记忆工具）→ 旧消息被递归摘要并"换出"到档案存储 → 上下文腾出空间 → 之后遇到需要旧信息的问题 → 检索"换入"。整个过程中**没有硬件 MMU，分页策略是 LLM 自己做的决策**——这正是"Agentic Memory"（第四节）的核心主张：记忆操作进入动作空间，由模型控制。

与真实操作系统的三点差别值得注意：

- **语义分页而非字节分页**：换出的不是原始字节，而是"摘要 + 索引"——信息有损（对应 9.5 的摘要漂移风险）；
- **策略驱动而非硬件驱动**：何时换页由 LLM 判断（可能出错），不是确定性的地址映射；
- **页 = 语义块**：档案里的"页"是记忆记录（对话片段、摘要、事实），检索靠语义相似度而非内存地址。

MemGPT 的启示：**上下文窗口就是"内存墙"**，显式记忆 + 分页让 Agent 在窗口有限的前提下处理任意长的历史——7.3 综述里"Hierarchical virtual context"家族（MemGPT、JARVIS-1）的核心思想即在于此。

#### 显式记忆的读写路径（完整梳理）

把前文的机制串成一条完整的 I/O 通路——显式记忆的**写路径**与**读路径**。

**写路径（记忆编码：从观测到可检索的记录）**，六步：

1. **感知与抽取**：从对话、工具反馈、文档中识别值得记的内容（salience 判断，对应 AgeMem 的 ADD 工具）；
2. **规范化与上下文显式化**（9.4）：消除指代、补全背景、标注置信度与来源，让记忆"十年后仍自洽"；
3. **冲突检测与收敛**（9.11/9.12）：与已有记忆比对，同实体聚合、槽位仲裁、抽象压缩；
4. **编码**：按组织形态转换——文本直接落库 / 向量化建索引 / 图谱三元组 / Memory3 式前向编码成稀疏 KV（8.5）；
5. **持久化与建索引**（9.7/9.8）：落盘 + 建 B-Tree / HNSW / 图索引，登记多维定位坐标（9.13）；
6. **异步固化与沙盒**（9.16）：候选先入队列，后台完成全部固化，坏记忆在沙盒层被拦截。

**读路径（记忆召回：从查询到参与决策）**，五步：

1. **查询理解**：把当前问题/状态转成检索条件（关键词 + 语义向量 + 实体 + 时间范围，9.13 多维定位）；
2. **多路粗召回**：向量库（HNSW）、全文索引、图谱遍历并行取候选；
3. **精排与冲突裁决**（9.11）：LLM 重排、去重、剔除过时记忆——RMM 的反射式重排器也作用于这一环；
4. **注入**：按形态接入计算——文本进上下文（RAG）/ K、V 拼进注意力（Memory3）/ 向量调制隐藏状态；
5. **参与决策**：注入后的证据通过注意力影响隐藏状态，最终改变输出分布；必要时再叠加解码层干预（CAD）。

读写两条路径由 Policy 统一调度（9.2）：**读路径决定"用哪些记忆"，写路径决定"存哪些记忆"，Policy 决定"何时读、何时写、何时忘"**。完整闭环是"读 → 想 → 写 → 再读"——一次决策既是读路径的消费者，也是写路径的生产者，这正是 7.1 因果闭环的工程全景。

### 8.7 讨论：仅靠知识注入能解决行业知识滞后吗？

回到本文开头的命题——"过去有没有帮它把今天的事做对"。行业知识滞后是参数化记忆的天然缺陷，那么**仅靠知识注入与更新（8.2 的四条路径）能完美解决吗？答案是否定的**，原因有四：

1. **成本追不上速度**：知识产生是连续的（新规、新版本、新产品），而参数化更新的成本是离散且高昂的（单条知识预训练写入约 2.24 TFlops，SFT 需要成对数据，知识编辑有规模化遗忘）。把"持续产生的事实"全部塞进权重，在经济学上不可持续。

2. **先验顽固导致吸收不良**：模型对训练分布的高频模式有强先验。行业新知识与旧先验冲突时，微调后的模型常常"假装学会"——评测集上答对，开放场景下又倒向旧答案。**模型能"记住"新知识，不等于能"消化"新知识**：消化需要新知识与既有知识结构建立连接，而参数化的局部更新很难保证这一点。

3. **单一格式不满足所有知识**：8.4 的成本公式说明，不同使用频率的知识各有最优格式。高频稳定知识适合进参数，低频易变知识进参数是浪费；反之，把高频知识放 RAG 每次重编码也是浪费。**只靠一种格式（无论参数还是 RAG）都无法全局最优**。

4. **可观测性为零**：参数化知识不可寻址、不可审计、不可回放。行业场景要求"这个回答依据的法规是哪条"，参数化记忆给不出 provenance；显式记忆与参考文本一一对应，天然可溯源。

因此，对行业知识滞后问题的务实答案是**分层记忆**：

- **高频、稳定、需要内化的知识** → 继续预训练 / LoRA 写进参数（先验）；
- **中频、时效、需要可溯源的知识** → 显式记忆（Memory3 式的 KV 记忆库），更新 = 更新知识库，零训练；
- **低频、一次性、高保真要求** → RAG / 上下文注入。

一句话总结：**参数化知识决定了模型"生来会什么"，显式记忆决定了模型"此刻知道什么"，而好的 Memory OS 负责让两者按读写效率各得其所。** 只靠把知识塞进权重，既塞不起，也消化不好，更追溯不了。

## 九、记忆的工程实现：从漂移到多级缓存管道

前两节分别讨论了"外部状态"（Ledger/Views/Policy）与"参数化知识"，这一节落到工程底层：记忆系统真正跑起来时，要面对信息漂移、存储分层、索引结构、载体选择、冲突消解和缓存调度。这一节的内容大量来自工程实践（数据库、缓存系统、向量检索），是《记忆工程》一书"实现层"的核心。

### 9.1 信息漂移：产生、危害与应对

#### 产生

信息漂移（information drift）指记忆库中的内容与外部真实世界渐行渐远。三个主要来源：

1. **概念漂移（concept drift）**：世界本身在变。"某公司的 CEO 是谁""某 API 的推荐用法"这类答案随时间改变。记忆库若只写不改，存的就是历史快照。
2. **语义漂移（semantic drift）**：同一段文字在不同语境下的含义漂移。"好"在商品评价里是褒义，在"好一个蠢主意"里是反讽。原始文本不动，检索它的语义空间却变了。
3. **表示漂移（representation drift）**：embedding 模型升级、分词器更换后，旧记忆向量的语义空间与新查询不兼容——向量索引还在，但"坐标系"换了。

#### 危害

- **错误固化**：过时知识被反复检索、注入上下文，模型据此生成看似自信的错误答案（自信的幻觉最难发现）；
- **污染派生层**：漂移的原始记忆被摘要、聚合成高层 view 后，错误被"提纯"进更抽象的层，污染面扩大且难以定位；
- **决策路径漂移**：Agent 的长程任务依赖早期记忆做后续决策，早期的一条漂移记忆可能让整条执行链偏航（错误级联）。

#### 应对

| 手段 | 机制 | 适用 |
|------|------|------|
| 时间戳 + 时态标注 | 每条记忆记录 valid_from / valid_to，检索时按查询时间过滤 | 概念漂移 |
| 新鲜度评分 | 访问越频繁、写入越新的记忆权重越高（类 Ebbinghaus 曲线） | 概念漂移 |
| 主动重写 | 新信息写入时检测冲突，覆盖旧事实（belief revision） | 概念漂移 |
| 定期重embed | 用新 embedding 模型重算旧记忆向量，迁移坐标系 | 表示漂移 |
| 语义版本化 | 同一实体保留多个时态版本，按需选择 | 时序知识图谱（Graphiti 思路） |

**核心原则**：漂移不可消灭，只能被**观测**（时间戳、来源、版本）与**治理**（更新、覆盖、过期）。这正是 Raw Ledger 存在的意义——没有账本，你甚至不知道哪条记忆已经过时。

### 9.2 记忆调度策略：多存储层协同

一个完整的 Memory OS 通常有 4 层存储，对应不同的读写成本与容量（与 8.4 的 Memory3 分层呼应）：

| 层级 | 载体 | 容量 | 延迟 | 写入成本 | 读取成本 |
|------|------|------|------|---------|---------|
| 工作记忆（L0） | 上下文窗口 / KV Cache | 小（4K~1M token） | 最低 | 0（随对话写入） | 低（注意力内） |
| 短期记忆（L1） | 会话缓冲区 | 中（小时级） | 低 | 极低 | 低 |
| 中期记忆（L2） | 高频索引存储（Redis/内存表） | 大（天级） | 中 | 中 | 中 |
| 长期记忆（L3） | 向量库 + 关系库 + 图谱 | 极大（月年级） | 高 | 高 | 高 |

**调度策略 = 何时把记忆从低层提升到高层，或从高层降级/淘汰**。典型规则：

1. **提升（promotion）**：会话中反复引用的记忆 → 写入短期；多次跨会话出现 → 升级为长期；
2. **降级（demotion）**：长期记忆中长期未被访问的 → 降为中期/归档；
3. **预取（prefetch）**：根据当前任务意图，提前把相关长期记忆拉进短期（类似 CPU 的 cache prefetch）。

调度本质是一个**成本-收益优化**：把高频访问的记忆放在读取便宜、但写入贵的层级。这与 8.4 的总成本公式是同一枚硬币的两面——那里选"格式"，这里选"层级"。

### 9.3 原子记忆单元

记忆不是整段的，而是由**原子记忆单元（atomic memory unit）**组成。原子单元是记忆系统的最小读写粒度，通常是一个结构化的 record：

```python
@dataclass
class MemoryUnit:
    id: str            # 全局唯一
    content: str       # 记忆内容（原始文本 / 摘要 / 三元组）
    mem_type: str      # episodic | semantic | procedural | preference
    created_at: float  # 写入时间戳
    last_access: float # 最近访问
    access_count: int  # 访问频率（淘汰算法的输入）
    ttl: float | None  # 生存时间（None = 永不过期）
    importance: float  # 重要性评分（0~1）
    source: str        # 来源（session_id / 文档 / 用户显式声明）
    links: list[str]   # 关联记忆 id（图谱边的基础）
```

**为什么要原子化**：

- **可更新**：只替换冲突的那一条，而不是整段历史；
- **可淘汰**：按单元做 TTL/频率淘汰，粒度精确；
- **可去重**：同 content 哈希判重，避免重复写入；
- **可追溯**：每条记忆都能回答"谁在何时写了我，依据是什么"——Provenance 的最小载体。

原子单元对应 8.4 成本公式里的"一条知识 $k$"：整个记忆系统的经济学，是建立在"单元"这个计数单位之上的。

### 9.4 记忆的表示：语义规范化、上下文显式化与不确定性外显

原子单元解决了"记忆怎么存"，这一节回答"记忆怎么写"。同样的内容，不同写法会让检索与推理效果天差地别。记忆的表示有三条纪律：

#### 语义规范化（Semantic Normalization）

同一含义的多种表述在写入前归一为统一形式：

- **指代消解**：把"它""该公司"替换为具体实体（"字节跳动"）；
- **同义归一**："用户喜欢 Python" 与 "用户偏好 Python" 统一为固定模板；
- **结构统一**：每条记忆按预设的语义模板组织（主体-谓词-客体，或 状态-条件-证据）。

程序上通常由 LLM 做一次"重写-归一"：

```python
def normalize(raw: str) -> str:
    return llm(f"""把以下信息规范化为记忆条目，要求：
    1. 消除指代，使用完整实体名
    2. 使用统一句式：谁/什么 + 状态或行为 + 条件/证据
    3. 保留数字、日期、名称等关键细节
    原文: {raw}""")
```

语义规范化的收益是**检索命中率**：向量检索对同义表达的召回远好于对口语化变体的召回，规范化让"写"与"查"落在同一个语义空间。

#### 上下文显式化（Contextualization）

记忆脱离产生它的会话后仍要可独立理解。原始记录往往是"上下文相关"的：会话里说"那个方案太贵了"，脱离上下文后没人知道"那个方案"指什么。写入时必须把隐式信息显式化：

- **时间显式化**：相对时间（"上周"）→ 绝对时间（2026-07-28）；
- **指代显式化**：把隐式主语/宾语补全；
- **场景显式化**：补记"在什么任务/什么约束下产生这条记忆"。

```python
def contextualize(raw: str, session_ctx: dict) -> str:
    return llm(f"""把会话片段改写为可独立理解的记忆，补全缺失的上下文。
    会话背景: {session_ctx}   # 时间、任务、用户、相关文档
    原始片段: {raw}""")
```

原则：**一条好记忆应该在十年后被读到依然自洽**。

#### 不确定性外显（Explicit Uncertainty）

记忆不是真理，很多是推测、传闻、未验证信息。把不确定性**显式地写进记忆本身**，而不是假装确定：

| 字段 | 含义 | 示例 |
|------|------|------|
| confidence | 置信度（0~1） | 0.7（用户随口一提）vs 0.98（用户明确确认） |
| evidence | 证据来源 | "用户原话：……" / "文档 §3.2" |
| status | 状态标记 | verified / inferred / contested / expired |

程序上，检索注入时低置信记忆要以条件语气呈现，避免模型把推测当事实：

```python
def render(mem: MemoryUnit) -> str:
    if mem.confidence < 0.6:
        return f"[推测·{mem.confidence:.0%}置信] {mem.content}"
    return mem.content
```

**核心认识**：记忆系统的价值不在于"记得多准"，而在于"知道自己有多不准"——不确定性外显是把"错误"从潜伏态变成可治理态的第一步（与 9.1 的漂移治理直接衔接）。

### 9.5 短期记忆：滑动窗口与语义摘要

短期记忆（L1）的容量有限（上下文窗口），两种技术协作管理：

#### 滑动窗口（Sliding Window）

只保留最近 $W$ 个 token（或 $N$ 条消息），更早的直接丢弃：

$$

\text{Window}(t) = \{x_{t-W+1}, \dots, x_t\}, \quad p(x_{t+1} \mid x_{<t}) \approx p(x_{t+1} \mid \text{Window}(t))

$$

程序实现就是双端队列（deque），左边弹出、右边压入：

```python
from collections import deque

window = deque(maxlen=W)          # maxlen 自动淘汰最旧
def append(x):
    window.append(x)              # 超过 W 自动 pop 左侧
    return sum(len(t) for t in window)  # 当前 token 占用
```

**优点**：O(1) 复杂度、实现简单、最近信息一定在。
**缺点**：窗口外的信息**完全丢失**——早期对话里的关键约束（"需求方要求必须兼容 IE11"）会被无声冲走。

#### 语义摘要（Semantic Summarization）

用 LLM 把窗口外的旧内容压缩成语义摘要，替代直接丢弃：

$$

S_j = \text{Summarize}(S_{j-1},\ x_{t_j} \dots x_{t_{j+1}})

$$

程序原理是**滚动摘要**（rolling summary）：维护一个摘要变量 $S$，每当窗口要溢出时，把 $S$ + 即将被挤出的内容一起交给 LLM 生成新摘要：

```python
summary = ""                       # 全局滚动摘要
def on_evict(evicted_tokens):
    global summary
    summary = llm.summarize(
        f"旧摘要: {summary}\n新内容: {evicted_tokens}"
    )                              # 摘要压缩 + 合并

def query_context():
    return f"[摘要] {summary}\n[最近] {window}"
```

**数学视角**：摘要是一个有损压缩映射，压缩率 $r = |S| / |X_{\text{evicted}}|$。它的核心风险是**摘要漂移**——低频关键信息在逐轮摘要中指数衰减：

$$

\text{Survival}(k, n) \approx \prod_{j=1}^{n} (1 - p_{\text{drop}}(k, j))

$$

每轮摘要都有一定概率丢细节，多轮后关键信息可能消失（这就是 7.3 综述里"Context-resident compression"家族的风险）。**缓解**：分层摘要树（RAPTOR 式：摘要再摘要，保留多粒度）、重要性加权（先让 LLM 标出关键句再摘要）、关键信息单独提炼成长期记忆再允许摘要丢弃。

**实践组合**：滑动窗口保证"最近不丢"，语义摘要保证"旧的不全丢"，两者叠加后短期记忆的覆盖范围从"窗口长度"扩展为"摘要 + 窗口"。

### 9.6 中期记忆：生存时间策略与访问频率淘汰

中期记忆（L2）容量介于会话与长期之间，需要主动淘汰。两种经典策略：

#### 生存时间（TTL, Time-To-Live）

每条记忆带过期时间，到期即删：

$$

\text{deadline}_i = \text{created\_at}_i + \text{ttl}_i, \quad \text{expire if } t > \text{deadline}_i

$$

TTL 适合**天生有时效**的记忆：临时任务状态、验证码、活动通知、一次性的会议纪要。

程序实现：优先队列（最小堆）按 deadline 排序，惰性删除（查询时发现过期才删）+ 定时清理（堆顶过期则批量弹出）：

```python
import heapq

heap = []  # (deadline, mem_id) 最小堆
def set_memory(mem_id, content, ttl_seconds):
    deadline = time.now() + ttl_seconds
    heapq.heappush(heap, (deadline, mem_id))
    store[mem_id] = content

def cleanup():                    # 定时调用
    now = time.now()
    while heap and heap[0][0] < now:
        _, mem_id = heapq.heappop(heap)
        store.pop(mem_id, None)
```

复杂度：写入 $O(\log n)$，批量清理 $O(k \log n)$。

#### 访问频率淘汰：LFU / LRU

**LFU（Least Frequently Used）**：淘汰访问次数最少的记忆。计数器 $c_i \leftarrow c_i + 1$ 每次命中递增：

```python
def access(mem_id):
    c[mem_id] += 1
def evict_lfu():
    victim = min(c, key=c.get)   # 计数最小的
    del c[victim]
```

**LRU（Least Recently Used）**：淘汰最久未访问的记忆。哈希表 + 双向链表，访问时把节点移到头部，淘汰尾部：

```python
class LRU:
    def __init__(self, cap):
        self.cap = cap; self.d = {}; self.head = Node(); self.tail = Node()
        self.head.next = self.tail; self.tail.prev = self.head
    def get(self, key):
        if key in self.d:
            node = self.d[key]
            self._move_to_head(node)      # 移到头部 = 标记"刚用过"
            return node.val
    def put(self, key, val):
        if key in self.d: self._move_to_head(self.d[key])
        else:
            node = Node(key, val); self.d[key] = node; self._add(node)
            if len(self.d) > self.cap:
                last = self.tail.prev     # 尾部 = 最久未用
                self._remove(last); del self.d[last.key]
```

LRU 复杂度：get/put 均 $O(1)$。这是 Redis `maxmemory-policy=allkeys-lru`、Memcached 默认淘汰的底层结构。

**LFU vs LRU 的选择**：

| 策略 | 淘汰依据 | 适合场景 | 缺陷 |
|------|---------|---------|------|
| TTL | 固定生存期 | 时效性强的记忆 | 无法处理"永远有用"的记忆 |
| LFU | 累计访问次数 | 访问模式稳定的记忆 | 早期冷门后来常用的记忆会被误杀 |
| LRU | 最近访问时间 | 突发热点访问 | 周期性访问的记忆会被误淘汰 |

**实践**：Memory OS 通常组合使用——TTL 管时效，LFU/LRU 管容量，再叠加重要性评分做加权（如 `score = importance × recency`，Mem0 / PowerMem 的时间衰减即此类）。

### 9.7 长期记忆检索：三类基础索引

长期记忆（L3）容量大，必须靠索引支撑检索。三类经典索引各有适用：

#### B-Tree

有序平衡多叉树，节点含多个键值，所有叶子在同一深度。适合**范围查询与有序扫描**：

$$

\text{Search: } O(\log_B N), \quad \text{存储: } O(N)

$$

- 磁盘友好：节点大小对齐页（4KB/16KB），一次 I/O 读一个节点；
- 用于 SQL 主键/普通索引、LevelDB 之前的传统关系库；
- 局限：只支持精确匹配与范围，不支持语义相似度。

#### LSM-Tree（Log-Structured Merge Tree）

**写优化**的结构：写入先进内存的 MemTable（跳表/红黑树），满了刷成不可变的 SSTable 落盘，后台按层级合并（compaction）：

$$

\text{Write: } O(1)~\text{内存} + O(1)~\text{顺序落盘}, \quad \text{Read: } O(\log N)~\text{~}~O(\#\text{levels})

$$

- 顺序写（而非 B-Tree 的随机写）让写放大远小于读放大，吞吐极高；
- 用于 LevelDB、RocksDB、Cassandra、HBase 以及大多数向量库的元数据存储；
- 代价：读路径要查多层 SSTable（可用布隆过滤器跳过不存在的层）；
- 对记忆系统：**写入频繁、读少写多的会话日志场景非常合适**。

#### 哈希索引

键 → 值的直接映射：

$$

\text{Get: } O(1)

$$

- 完美支持"按记忆 id 精确取回"；
- 无顺序、无范围查询，容量受内存限制（或用可扩展哈希落盘）；
- 用于 Redis、Memcached、以及所有 KV 场景。

**三类索引在记忆系统中的分工**：

| 索引 | 查询类型 | 记忆场景 |
|------|---------|---------|
| B-Tree | 有序/范围 | "2026 年 3 月到 5 月的所有会话记录" |
| LSM-Tree | 高频写入 + 点查 | 会话日志、原始 ledger 的 append-only 流 |
| Hash | O(1) 点查 | 按 memory id / 用户 id 取回 |

### 9.8 复杂索引：HNSW 向量索引与知识图谱关联结构

语义检索（"和这条记忆相关的记忆有哪些"）需要**近似最近邻（ANN）**索引。最主流的是 HNSW。

#### HNSW（Hierarchical Navigable Small World）

把"小世界网络"（六度分割式的高连通图）与"跳表"的分层思想结合：

- **多层图**：第 0 层包含全部节点；越往上层节点越少、边越长——上层是"地图"，下层是"街道"；
- **构建**：每个节点按几何分布随机分配层数（层越高节点越少），逐层贪心插入，每层用候选队列（$ef\_construction$）选邻居，用 $M$（max_degree）限制连接数；
- **检索**：从最高层入口开始，每层贪心走向离查询最近的节点，然后下探一层，重复直到第 0 层做精细搜索（$ef\_search$ 控制候选队列长度）。

复杂度：查询约 $O(\log N)$ 次距离计算（对比暴力 $O(N)$），精度通常可达 95%+（牺牲 5% 换取几个数量级的加速）。

```python
def search_hnsw(query_vec, ef_search=64):
    cur = entry_point                    # 最高层入口
    for layer in range(top_layer, 0, -1):
        cur = greedy_search(query_vec, cur, layer)   # 本层贪心
    candidates = greedy_search(query_vec, cur, 0, ef_search)  # 底层扩展
    return top_k(candidates)
```

工程注意：HNSW 是**内存型**索引（图结构在内存），海量记忆需分片；插入时不可并发构建（vearch 等做了实时化改造）；删除是"软删除"（标记 + 后台清理）。

#### 基于知识图谱的关联结构

向量索引回答"语义上像不像"，知识图谱回答"**结构上连不连**"。记忆图谱以实体为节点、关系为边（三元组 $(\text{subject}, \text{predicate}, \text{object})$），支持多跳推理：

$$

\text{User} \xrightarrow{\text{likes}} \text{FPV} \xrightarrow{\text{related\_to}} \text{Gyroflow} \Rightarrow \text{User 可能关心 Gyroflow}

$$

与向量索引的对比：

| 维度 | 向量索引（HNSW） | 知识图谱 |
|------|----------------|---------|
| 查询方式 | 语义相似度 top-k | 结构遍历/图查询（Cypher） |
| 擅长 | "找内容相似的记忆" | "找有关联的记忆、多跳推理" |
| 时效 | 需要重embed | 边带时间戳（Graphiti 时态图） |
| 短板 | 不表达关系语义 | 构建成本高、稀疏数据效果差 |

**实践**：混合双通道——HNSW 做粗召回（语义候选），图谱做精过滤/扩展（关系过滤 + 一跳邻居补充），两者在重排序阶段融合。这是 Mem0、Graphiti、PowerMem 混合检索的共同形态。

### 9.9 记忆的载体形式：激活态与外部显式载体

记忆可以按"存在哪里、如何被使用"分为两类载体：

#### 激活态载体（Active / In-context Carrier）

**存在形式**：上下文窗口内、KV Cache 里、注意力计算路径上的信息。包括当前对话、检索注入的 RAG 段落、System Prompt 中的指令与画像。

**特性**：

- 读取成本最低——就在注意力里，随模型前向自动参与计算；
- 容量受窗口限制，且随对话推进被挤出（8.1 的"知识穿越"在这反而是零成本）；
- **易失**：会话结束即消失（除非显式导出）；
- 更新极快：改写提示词 = 立即生效。

**激活态记忆的两种具体形态：隐藏状态与 KV Cache**。激活态载体内部还可以再分：**隐藏状态（hidden state）与 KV Cache**。两者都在注意力计算路径上、都是"会话结束即消失"，但一个是"计算中的状态"，一个是"过去的存档"。

**隐藏状态（Hidden State）：模型"此刻在想什么"**。解码器 Transformer 的每一层是一个残差结构：输入 $h^{(l-1)}$ 先经注意力"从前文搬运信息"，再经 FFN"激活内部特征"（8.1 的分工），两者都加回原向量：

$$

h^{(l)} = h^{(l-1)} + \mathrm{Attn}\big(\mathrm{LN}(h^{(l-1)})\big) + \mathrm{FFN}\big(\mathrm{LN}(\tilde{h}^{(l)})\big)

$$

$h^{(l)} \in \mathbb{R}^{d}$ 就是第 $l$ 层输出的**隐藏状态**——每个 token、每层各有一个。它的含义有三层：

- **它是"当前计算的中间结果"**：把上下文 $x_{<t}$ 压缩成一个 $d$ 维分布式表示，随层数升高越来越抽象（低层偏向词法/句法，高层偏向语义/事实）；
- **它是"思维的状态"**：最后一层、最后位置的隐藏状态 $h^{(L)}_T$ 直接决定下一个 token 的概率：

$$

p(y_t \mid x_{<t}) = \mathrm{softmax}\big( W_{\mathrm{lm}}\, h^{(L)}_T \big)

$$

**模型每说一个字之前，"脑子里"的状态就是这个向量**；

- **它是知识编辑与探测的作用点**：8.2 里因果追踪还原的、ROME 计算键 $k^*$ 用的、LAMA 探针读取的，都是隐藏状态；激活添加（activation steering）也是在隐藏状态上叠加方向向量。隐藏状态是**唯一能"读出/改写"模型内部认知的载体**。

**KV Cache：注意力空间的"对话存档"**。注意力要算当前 token 与所有历史 token 的相似度，需要每个历史 token 的键 $K$ 和值 $V$。**KV Cache 就是把已算过的历史 token 的 K、V 全部缓存下来**，生成下一个 token 时只算新 token 的 $Q, K, V$，历史部分直接复用，避免每步重算整个序列的注意力：

$$

\mathrm{Attn}(Q_t, K_{\le t}, V_{\le t}) = \mathrm{softmax}\!\Big( \frac{Q_t K_{\le t}^{\mathsf{T}}}{\sqrt{d_h}} \Big) V_{\le t}

$$

其中 $K_{\le t} = [\,K_{\text{cache}},\, K_t\,]$ 表示"历史缓存的 K 与当前 token 新算的 K"拼接。KV Cache 的大小约等于 $2 \times L \times n_{\mathrm{kv}} \times d_h \times T$（K、V 两份，$L$ 层，$n_{\mathrm{kv}}$ 个 KV head，$d_h$ 头维度，$T$ 个 token），这就是长对话"越聊越占显存"的直接来源，也是 8.5 里 GQA 要砍 KV head 数的原因。

**隐藏状态 vs KV Cache 的区别**：

| 维度 | 隐藏状态 | KV Cache |
|------|---------|----------|
| 本质 | 当前 token 在每层的**计算中间结果** | 历史 token 的 **K/V 存档** |
| 数量 | 每层 × 每个位置各一个（随层变化） | 每层 × 每个历史位置各一对（固定不变） |
| 更新方式 | 每生成一个 token 全量重算（受新上下文影响） | 只增量追加新 token 的 K/V，历史部分零重算 |
| 角色 | "此刻的思维"（working state） | "说过的内容"（conversation record） |
| 生命周期 | 单步计算结束即被丢弃（除非显式导出） | 会话期间常驻显存，会话结束释放（可持久化为 prompt cache） |
| 可干预性 | 探针、知识编辑、steering 的作用点 | Memory3 持久化的对象、prompt cache 的对象 |

一句话：**隐藏状态是"现在正在想什么"，KV Cache 是"之前说了什么"**。前者随每一步思考流动、被变换，后者作为固定的上下文供注意力反复查阅。两者都是激活态记忆（易失、随会话结束），与持久化的显式记忆（8.6）之间只隔"导出"一步——把隐藏状态导出就是向量记忆（embedding 记忆库），把 KV Cache 导出就是 Memory3 式显式记忆。



#### 外部显式载体（External Explicit Carrier）

**存在形式**：持久化的存储——数据库、向量库、文件、知识图谱。

**特性**：

- 持久、可审计、可跨会话共享；
- 读取需要先检索再注入（多一跳）；
- 容量近乎无限，可承载完整历史；
- 更新需要写操作（写入成本，见 8.4 的成本公式）。

**两者的关系**：激活态是"被想起的记忆"，外部显式是"可被想起的记忆"。Memory OS 的调度（9.2）本质上就是在这两种载体之间搬运——**检索 = 外部 → 激活**，**写入 = 激活 → 外部**。8.5 的 Memory3 显式记忆是两者的桥梁：它把外部载体做成 KV 形态，让"外部"以接近激活态的成本参与注意力。

### 9.10 结构化记忆的具体载体形式

结构化记忆指有固定 schema 的记忆，具体载体有三类主流：

| 载体 | 结构 | 优势 | 典型场景 |
|------|------|------|---------|
| 关系表（SQL） | 行 × 列 | 强约束、事务、复杂查询（JOIN） | 用户画像、偏好、KV 元数据 |
| 键值/文档（Redis / MongoDB / JSON） | 键→文档 | 灵活 schema、低延迟 | 会话状态、配置、记忆单元本身 |
| 知识图谱（Neo4j / RDF） | 节点-边-属性 | 关系表达、多跳推理 | 实体关联、时序事实 |

选型原则：**schema 稳定且查询复杂 → 关系表；schema 多变且读多写多 → 文档；关系是核心价值 → 图谱**。工程上常用"组合拳"：SQLite/Postgres 存元数据与记忆单元，Redis 做热点缓存（L2），向量库 + 图谱并行服务语义与关系检索（L3）。

### 9.11 非结构化记忆冲突的解决

非结构化记忆（自然语言片段、摘要、对话记录）之间常互相矛盾："用户喜欢 Python" vs "用户改用 Rust 了"。冲突不解决，检索到的就是自相矛盾的上下文。两种主流解法：

#### 语义聚类（Semantic Clustering）

把语义相近的记忆聚成一簇，簇内冲突通过"多数投票 / 时间加权"裁决：

$$

\text{sim}(m_i, m_j) = \cos(\text{emb}(m_i), \text{emb}(m_j)) \ge \tau \Rightarrow \text{同簇}

$$

```python
clusters = []  # 增量聚类
def upsert(memory):
    emb = embed(memory.content)
    for c in clusters:
        if cos(emb, c.center) >= THRESHOLD:
            c.members.append(memory)
            c.center = mean_emb(c.members)   # 簇心随成员更新
            resolve_conflicts(c)             # 时间新者胜 / 投票
            return
    clusters.append(Cluster(center=emb, members=[memory]))
```

优势：无额外 LLM 调用、可解释（簇=主题）；劣势：阈值难定、跨簇冲突管不到。

#### 大模型重排序 / 裁决（LLM Re-ranking）

把候选记忆连同上下文交给 LLM 裁决，让模型选出最相关、最一致的一条：

```python
def rerank(candidates, query):
    prompt = f"""以下记忆与当前问题相关，请按相关性与一致性排序，
    排除与最新事实冲突的过时记忆:
    问题: {query}
    记忆: {[m.content for m in candidates]}
    返回排序后的记忆 id 列表。"""
    ordered = llm(prompt)
    return [candidates[i] for i in ordered]
```

优势：语义理解强，能处理"表面相似实则矛盾"的复杂情况；劣势：每次裁决一次 LLM 调用（延迟 + 成本），且模型自身可能误判。

**实践分层**：先用语义聚类做粗过滤（把 100 条候选压到 5 条），再对簇内/簇间少数冲突用 LLM 精裁。**聚类管量，LLM 管质**。

### 9.12 多条记忆的收敛：同一实体的聚合、槽位仲裁与抽象压缩

9.11 解决了"冲突时选哪条"，这一节更进一步：**多条相关记忆如何合并成更高质量的一条**。收敛不是简单拼接，而是围绕**实体**展开的三层操作——先把同一实体的零散记忆聚合起来，再对实体属性槽位做仲裁，最后把冗余的具体记忆压缩为抽象表示。三种机制：

#### 机制一：同一实体的聚合（Entity Aggregation）

多条记忆描述的是同一个实体（用户、项目、概念、文档），第一步是把它们归并到一起。前提是**实体解析**——判断两条记忆是否指向同一实体：

```python
def resolve_entity(mem: MemoryUnit, entities: dict[str, Entity]) -> Entity | None:
    # 三种判定信号：精确名称、别名表、语义相似度
    if mem.entity_name in entities:
        return entities[mem.entity_name]
    alias = alias_table.lookup(mem.entity_name)          # 别名/指代消解
    if alias and alias in entities:
        return entities[alias]
    emb = embed(mem.content)
    best = max(entities.values(), key=lambda e: cos(emb, e.embedding))
    if cos(emb, best.embedding) > ENTITY_THRESHOLD:
        return best
    return None                                           # 无法归并 → 新建实体
```

解析成功后执行聚合：把多条记忆的属性、证据、关联边并入实体：

```python
def aggregate(entity: Entity, mems: list[MemoryUnit]):
    for m in mems:
        entity.attributes.update(m.attributes)   # 属性合并（并集）
        entity.evidence.append(m.id)             # 证据链追加
        entity.links |= m.links                  # 关联边合并
```

要点：聚合是**并集操作**——同一实体的多条记忆互补信息全部保留，不丢弃任何一条的证据。用户画像、项目状态这类实体级记忆，正是这样从零散对话记录中"长"出来的。

#### 机制二：槽位仲裁（Slot Arbitration）

实体有**槽位**（slot）——预定义的属性位，如 `User.primary_language`、`Project.status`、`Doc.author`。多条记忆竞争同一槽位时，必须裁决谁的值"转正"：

```python
SLOTS = {"primary_language", "status", "author"}

def arbitrate_slot(entity: Entity, slot: str, candidates: list[MemoryUnit]) -> MemoryUnit:
    # 仲裁规则：置信度 × 新近度 × 来源可信度的加权评分
    def score(m: MemoryUnit) -> float:
        return (m.confidence * 0.5
                + recency(m.created_at) * 0.3
                + source_trust(m.source) * 0.2)
    winner = max(candidates, key=score)
    for c in candidates:
        if c is not winner:
            c.status = "superseded"              # 落选者进版本链
            winner.links.append(c.id)
    entity.slots[slot] = winner.value
    return winner
```

要点：**落选值不删除**，标记 superseded 并保留版本链——新版本后来被证伪时可以回退（与 9.1 的 belief revision 呼应）。槽位仲裁是收敛中最"像数据库"的一步：它把记忆库变成一张可一致性更新的属性表，冲突不再靠"碰运气"，而是按可解释的评分规则裁决。

#### 机制三：抽象压缩（Abstract Compression）

同一实体的记忆越聚越多，细节不必全部保留。抽象压缩把多条具体记忆**归纳为一条抽象记忆**，丢弃可重建的细节：

$$

|\text{Abstract}| \ll \sum_{i} |m_i|,\quad \text{Abstract} = \text{LLM}\big(\text{归纳}(\{m_1,\dots,m_k\})\big)

$$

```python
def compress(entity: Entity, mems: list[MemoryUnit]) -> MemoryUnit:
    abstract = llm(f"""把以下关于 {entity.name} 的 {len(mems)} 条记忆压缩为一条抽象记忆：
    - 保留：稳定属性、结论性偏好、跨条一致的模式
    - 丢弃：一次性事件细节、可重建的原始过程
    {[m.content for m in mems]}""")
    return MemoryUnit(
        content=abstract,
        mem_type="semantic",          # 从 episodic 升格为 semantic
        links=[m.id for m in mems],   # 指向源记忆（可解压回查）
        confidence=min(m.confidence for m in mems)  # 取最保守置信度
    )
```

数学视角：抽象压缩是一个**有损归纳映射**，压缩率 $r = |\text{Abstract}| / \sum_i |m_i|$。它把 episodic（具体事件）记忆升格为 semantic（抽象知识）记忆——这正是 7.2 分类学里 episodic → semantic 的工程实现。风险是**过度抽象**：被压缩掉的场景细节（"当时在什么条件下用户说喜欢 FPV"）往往正是后续检索需要的上下文，所以抽象记忆必须保留指向源记忆的 links，保证可解压回查。

**三机制的组合**：聚合管"归并"（同一实体的记忆并到一起），仲裁管"定值"（槽位冲突时谁胜出），压缩管"瘦身"（冗余细节归纳为抽象）。三者在记忆的生命周期中循环执行：新记忆写入 → 聚合进实体 → 槽位仲裁 → 定期压缩——记忆库在一次次收敛中保持**规模可控、语义一致、结构正确**，这是检索质量（9.7/9.8）与长期可扩展性的前提。

### 9.13 多维记忆定位空间

单一索引只能回答一种"找记忆"的方式。多维记忆定位空间用多个正交维度给每条记忆建立坐标，检索时可按任意维度组合定位：

| 维度 | 取值示例 | 检索方式 |
|------|---------|---------|
| 时间 | 2026-03-15 14:02 | B-Tree 范围查询 |
| 主题/语义 | "FPV 调参" | HNSW 向量检索 |
| 实体 | User, Gyroflow, Betaflight | 图谱节点查询 |
| 类型 | episodic / semantic / procedural | 过滤条件 |
| 来源 | session-42 / 文档X / 用户声明 | 过滤条件 |
| 重要性 | 0.8 | 排序加权 |

每条记忆 = 高维空间中的一个点：$(\text{time}, \text{emb}, \text{entities}, \text{type}, \text{source}, \text{importance})$。

检索时按查询意图组合维度：回忆"上周讨论过的 FPV 调参" = 时间范围（B-Tree）+ 语义向量（HNSW）+ 实体过滤（图谱），三路结果做融合重排。**多维空间的价值在于把 9.2 的调度、9.7/9.8 的索引、9.11 的冲突解决统一到同一个"按坐标取记忆"的框架里**。

### 9.14 解耦结构：长历史的持续吸收与调用

"长历史存入记忆库，以解耦结构支持持续吸收与调用"——这里的**解耦结构（decoupled structure）**指把记忆的"原始真相"与"使用视图"分离成互相独立的层，各自按自己的节奏演化：

1. **存储与使用解耦**：写入路径（append-only 的 Raw Ledger）与读取路径（Views）物理/逻辑分离。历史永远可追加，视图随时可重建；
2. **内容与索引解耦**：原始文本存在对象存储/文档库，索引（向量、图谱、倒排）单独维护。embedding 模型升级时只重算索引，不动原文；
3. **历史与工作集解耦**：完整历史在 L3，当前任务只加载"工作集"（摘要 + 相关切片）到 L1/L2——模型永远只面对小上下文，却能通过检索触及全部历史。

**为什么必须解耦**：如果"存储"和"使用"耦合（比如把整个历史直接塞进上下文），长历史会撑爆窗口（上下文爆炸）、拖慢推理（注意力 O(n²)）、污染注意力（8.5 讨论过的 lost in the middle）。解耦后：

$$

\text{调用}(t) = \text{Retrieve}(\text{Index}( \text{History}_{<t} ),\ \text{Query}_t) \rightarrow \text{Working Set}_t

$$

持续吸收变成**增量写入 + 异步固化**：新事件 append 进 ledger → 后台抽取实体/生成摘要 → 增量更新索引。全程无全量重扫，历史再长也只是"多了一页账"，而不是"多了一倍上下文"。

### 9.15 记忆的回溯与调试

记忆系统是"看不见的内部状态"，一旦 Agent 行为异常（答错、遗忘、幻觉），工程师需要能**回答"哪条记忆导致了这次行为"**。这就是记忆的回溯（traceability）与调试（debuggability）。

#### 回溯：从行为到记忆的单向还原

每条记忆都应保留完整的**溯源链**（provenance chain）：

$$

\text{Memory}_i \xleftarrow{\text{写入}} \text{Candidate}_j \xleftarrow{\text{产生}} \text{Session}_k \xleftarrow{\text{来源}} \text{原始事件}

$$

程序上为每条记忆记录三个来源字段：

```python
@dataclass
class Provenance:
    session_id: str      # 哪个会话写的
    source_event: str    # 哪条原始事件（工具调用 / 对话轮 / 文档段落）
    cause: str           # 写入原因（显式声明 / 抽取 / 摘要 / 冲突更新）
    created_by: str      # 哪个组件写的（LLM 抽取器 / 规则 / 用户）
```

有了溯源链，"这条记忆哪来的"变成一条 SQL/图查询，而不是猜。

#### 调试：记忆系统的"断点"

与代码调试对应，记忆系统需要三类调试工具：

| 调试动作 | 对应代码概念 | 记忆系统实现 |
|---------|------------|-------------|
| 单步观察 | 断点 | 会话级记忆回放：逐步展示每轮检索注入的记忆 |
| 检查状态 | 变量查看 | 记忆查看器：按 id/主题/时间浏览单元、视图、图谱 |
| 定位污染 | 栈回溯 | 影响分析：给定输出 token，反查参与计算的记忆（类 attention 归因） |
| 回滚 | git revert | 记忆快照恢复：把某时间点之后的所有变更回滚 |

关键支撑是**不可变 ledger + 可重建视图**（9.14 解耦结构的直接收益）：因为 Raw Ledger 是 append-only 的，任何时刻的记忆库状态都能从 ledger 重建；因为 Views 是派生的，怀疑某个 view 错了可以单独重建对比。

```python
def debug_memory(mem_id: str, at_time: float | None = None):
    """查看某条记忆的完整生命周期"""
    events = ledger.query(mem_id=mem_id, at_time=at_time)
    for e in events:
        print(f"[{e.ts}] {e.op}  {e.detail}")
    # 输出示例:
    # [10:02:01] CREATE  content="用户偏好 FPV 调参" conf=0.9
    # [10:45:00] UPDATE  content="用户偏好 FPV + Gyroflow 调参" cause=冲突仲裁
    # [11:30:00] RETRIEVE by session-88  score=0.87
```

#### 为什么必须可回溯

- **漂移定位**（9.1）：一条过时记忆导致错误，没有溯源链就无法知道它何时、因何写入，也无法评估是否该批量清理同类；
- **责任划分**：多 Agent / 多来源写入时，知道"谁写的"才能判断是抽取器 bug 还是数据源问题；
- **信任建立**：行业场景要求"这个结论的依据是哪些记忆"，溯源链是唯一能给出答案的机制（与 8.5 显式记忆的 provenance 优势一致）。

**核心原则**：记忆系统应该像数据库一样提供 `EXPLAIN` 与 `binlog`——既能解释一次检索为什么命中，也能回放任何时刻的完整状态。

### 9.16 写入管道：同步候选、异步固化与沙盒层

9.2 的调度讨论了"读"的分层，这一节讨论"写"的管道。记忆写入如果全部同步阻塞在请求路径上（抽取 → 规范化 → 建索引 → 写图谱 → 落盘），延迟会拖垮 Agent 的交互节奏。工程上的标准解法是**写入管道**：**同步产生候选，异步完成固化**。

#### 管道结构

```

   写入请求
     │
     ▼
┌─────────────────┐  同步：低延迟，立即返回
│ ① 候选生成        │  抽取 → 规范化(9.4) → 冲突预检 → 生成 Candidate
└─────────────────┘
     │ 投递
     ▼
┌─────────────────┐  异步：后台队列，批量消化
│ ② 异步固化        │  写 ledger → 建索引 → 更新图谱 → 触发收敛(9.12)
└─────────────────┘
     │
     ▼
   记忆库（持久层）
```

**第 ① 步（同步候选）**：在请求路径上只做轻量工作——抽取候选记忆、语义规范化、与当前上下文快速比对是否有明显冲突，然后**立即返回**给调用方（"记忆已受理"）。候选进入写入队列即算成功，不等待固化完成。

**第 ② 步（异步固化）**：后台 worker 从队列取候选，完成重活——写入 Raw Ledger、更新向量/图谱/全文索引、必要时触发多记忆收敛。即使固化失败，请求路径也不受影响（Agent 继续工作，记忆稍后补偿）。

#### 异步写入的三大配套机制

异步化引入了同步方案没有的三个问题，必须有配套机制：

##### 机制 A：候选记忆的可追踪状态

每条候选不是"进队列就完事"，而是一个**有状态对象**，全程可查询：

```python
class CandidateState(Enum):
    PENDING    = 1   # 已入队，等待 worker
    PROCESSING = 2   # 正在固化
    COMMITTED  = 3   # 固化完成，已写入记忆库
    FAILED     = 4   # 固化失败，待重试/补偿
    DROPPED    = 5   # 已放弃（重试耗尽）

@dataclass
class Candidate:
    id: str
    content: str
    state: CandidateState
    retry_count: int = 0
    created_at: float
    last_update: float
```

配套一个状态查询 API，Agent 或运维可以随时问"那条记忆写好了没"。

##### 机制 B：写入队列的幂等处理

异步 + 重试意味着**同一条候选可能被投递多次**（网络重发、worker 崩溃重启、超时重试）。如果每次投递都执行固化，会产生重复记忆。解决：**幂等键（idempotency key）**。

```python
def enqueue(candidate: Candidate) -> bool:
    key = hash(candidate.content + candidate.session_id)  # 幂等键
    if idempotency_store.contains(key):    # 已处理过 → 直接返回成功
        return True
    idempotency_store.mark(key)            # 先标记，再入队
    queue.push(candidate)
    return True
```

配合固化阶段的**去重校验**（9.3 提到 content 哈希判重），即使两条不同来源的重复候选，也只会保留一条。

##### 机制 C：失败后的补偿与回滚

异步固化可能半途失败（ledger 写好了、索引没建成）。需要**补偿（compensation）与回滚（rollback）**策略：

```python
def solidify(candidate: Candidate):
    try:
        ledger.append(candidate)              # 1. 写账本
        index.build(candidate)                # 2. 建索引
        graph.upsert(candidate)               # 3. 更新图谱
        candidate.state = COMMITTED
    except IndexBuildError:
        ledger.rollback(candidate.id)         # 回滚已写部分
        candidate.state = FAILED
        retry_with_backoff(candidate)         # 指数退避重试
    except GraphError:
        index.delete(candidate.id)            # 补偿：删掉已建索引
        ledger.rollback(candidate.id)
        candidate.state = DROPPED             # 重试耗尽，丢弃并告警
        alert("记忆固化失败", candidate.id)
```

关键设计：**每一步都要可逆**（rollback），或**每一步都要可补偿**（compensate）。写入顺序要按"可回滚性"排列——先写可回滚的，后写难回滚的，失败时从后往前撤销。

#### 沙盒层：固化的安全网

异步固化的最后一道防线是**沙盒层（Sandbox Layer）**——候选记忆不直接写入正式记忆库，而是先进沙盒（隔离的暂存区）验证，验证通过才"转正"。

**沙盒层的职责**：

| 检查项 | 内容 | 拦截目标 |
|--------|------|---------|
| 有害性过滤 | 敏感信息、注入攻击、违规内容 | 恶意/有害记忆 |
| 一致性校验 | 与 9.11/9.12 的冲突与收敛检查 | 矛盾、重复记忆 |
| 质量门槛 | 置信度、完整性、可理解性评分 | 低质量候选 |
| 策略灰度 | 新抽取策略的候选先小流量试跑 | 策略回归 |

```python
def sandbox_validate(candidate: Candidate) -> bool:
    if toxicity_filter(candidate.content):   return False   # 有害
    if not consistency_check(candidate):     return False   # 冲突未解决
    if candidate.confidence < MIN_CONF:      return False   # 质量不达标
    return True

def pipeline(candidate: Candidate):
    if sandbox_validate(candidate):
        solidify(candidate)                  # 通过 → 正式固化
    else:
        candidate.state = DROPPED            # 拦截 → 丢弃并记录原因
        log_rejection(candidate, reason="sandbox")
```

**为什么需要沙盒**：记忆是**被信任后反复使用**的状态——一条坏记忆一旦进入正式库，会被检索、注入、收敛、再派生，污染面指数放大（9.1 的"污染派生层"）。沙盒把"写坏"的成本从"污染全库"降为"丢弃一条候选"，是记忆系统容错性的最后一层保险。

**完整写入管道小结**：同步产生候选（低延迟）→ 入队（幂等）→ 异步固化（可追踪状态）→ 沙盒验证（安全网）→ 失败补偿回滚（可逆）。这一管道让"写记忆"从阻塞的副作用变成可靠的异步服务——读侧的分层调度（9.2）与写侧的异步管道共同构成记忆系统的完整 I/O 路径。
