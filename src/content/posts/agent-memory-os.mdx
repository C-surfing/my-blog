> Agent Memory 不是"存储"，而是一个把历史转成可用信息并影响决策的闭环系统。

## 一、Memory 的三个核心命题

Agent 里的 Memory 要回答的问题是：**过去有没有帮它把今天的事做对**。靠一个 Markdown 文件甚至一个数据库都远远不够——Agent 需要一个小的 **Memory OS**。

经过近年来的探索，Agent Memory OS 可以抽象为三个词：**Raw Ledger、Views、Policy**，分别类比操作系统里的原始日志、索引与缓存、调度规则。

### 命题 A：Memory 不是"存储"，而是可被决策利用的外部状态

如果把 Agent 看成一个从输入到输出的函数，仅仅"存了很多历史"并不构成能力。能力来自：在当前状态下，历史能否以某种形式影响决策分布。

Memory 的价值不在于"存了多少历史"，而在于**这条从历史到当前决策的通道是否有效**。它要么进入上下文（证据/摘要/子图），要么直接参与决策（例如对输出分布做调制）。

### 命题 B：Memory 的最小闭包是 Ledger、Views、Policy

| 组件 | 类比 | 职责 |
|------|------|------|
| **Raw Ledger** | 账本/黑匣子 | 按发生顺序保留写入、修改、删除和反馈，可审计 |
| **Derived Views** | 缓存+索引+物化视图 | 从账本加工出的各种"便于查找的版本"：向量索引、全文索引、知识图谱、时间线 |
| **Policy** | 调度器/控制回路 | 决定何时读、读多少、何时写、如何更新、如何遗忘 |

三者缺一，系统要么不可治理（没有账本），要么不可用（没有索引/抽象），要么不可持续迭代（没有可 A/B 的控制点）。

### 命题 C：Memory 的基本单位是 event 序列

最通用的 ledger 事件应包含：作用域（scope）、时间戳、输入观测、系统动作、记忆变更（ADD/UPDATE/DELETE/NONE）、反馈信号、决策元数据。

Event 序列是"真相来源"，但太底层。真正把历史变成能力的是 **views**（对 event 的重组织/压缩/索引/技能化）和 **policy**（决定触发哪些 view、怎么更新）。

因此，Memory 的本质是一个闭环系统：

---

> **核心闭环**：Raw Ledger（权威）→ Views（可用）→ Policy（控制）→ Commit（回写）→ Provenance（可回放）

## 二、System 1 + System 2 的双系统设计

### 为什么需要"非空"的 System 2

- **System 1**：快速工作的通用 Agent（大模型+工具），读懂问题、写代码、调用搜索、生成回答
- **System 2**：较慢的外部记忆回路，负责保存、检索、更新、压缩和遗忘，像操作系统内核与后台服务

如果 System 2 不发挥作用，记忆能力只能通过 RL post-training 固化到 LLM 权重中，很难保证特化后仍保持通用泛化能力。

### "记忆能力"与"Agent 通用能力"为什么是"相对正交"的

**正交的一侧**：同一个 base model 接入不同记忆策略就能显著改变长程表现；而同一套记忆 infra 也往往能服务多种不同的 base model。这种跨模型可复用意味着能力更多绑定在接口与外部状态上。

**非正交的边界**：检索噪声、错检、时序冲突会直接破坏推理（引发幻觉）；同时检索策略依赖 Agent 的自我评估能力。因此更准确的说法是"相对正交 + 存在可控交叉项"，而 System 2 的可观测性、可回放能力正是将交叉项显式化、可诊断。

### 非参数化逼近参数化 Memory

参数化记忆（parametric memory）：经验写进模型权重（训练/微调），推理时不需要额外检索。
非参数化记忆（non-parametric memory）：经验写在外部状态里（ledger + views + skill pool），通过检索/聚合/注入影响决策。

System 2 的意义就是：**把在线适应的主战场从模型权重挪到外部记忆状态与控制策略上**。

**记忆对决策的调制方式**：新的动作倾向 = 模型原本的判断 + 记忆带来的修正 Δ（Delta）

Δ 是"外置的可控偏置"——不需要改模型权重，但能改变决策分布。

## 三、非参数化 Memory 的上限由什么决定

### 1. 接口带宽（注入容量）

无论是 passage、graph、skill，最终都要通过 Context Bridge 让 System 1 用上它。注入通道存在预算约束——外部记忆再大也没用，真正起作用的是每一步你注入多少有效信息。

### 2. 检索与聚合误差

Views 是从 Raw Ledger 派生出的近似结构。近似会带来错检、漏检、时序冲突、语义漂移，直接污染修正项 Δ。因此上限不仅取决于"存了多少"，更取决于误差是否能被治理（可观测、可溯源、可回放）。

### 3. Policy 的学习与控制

存太多污染，存太少学不到；召回太多挤占上下文，召回太少缺证据；错删一条长期偏好，个性化一路歪下去。

非参数化 Memory 的真正瓶颈往往不是存储后端，而是 **policy**。

## 四、核心模块设计

### Policy 层：Rubrics 不可持续

打破传统 engineers 的思维禁锢：基于预定义规则（rubrics）的 policy 不可持续，必须用 model 来处理。目前最可行的路径是 **Agentic Memory**——将记忆操作彻底工具化，整合进 Agent 的动作空间，让模型像控制手臂一样控制记忆。

记忆工具分类：

| 记忆层 | 操作 | 功能 | 对应参数化行为 |
|--------|------|------|---------------|
| 长期记忆 (LTM) | ADD | 存储新知识 | 梯度更新 |
| LTM | UPDATE | 修正旧知识 | 权重调整 |
| LTM | DELETE | 移除过时信息 | 剪枝 |
| 短期记忆 (STM) | RETRIEVE | 语义搜索并注入 | 激活相关神经元 |
| STM | SUMMARY | 压缩对话历史 | 抽象表征 |
| STM | FILTER | 移除无关 Context | 注意力机制 |

### 关键工作：AgeMem 的分阶段 RL 训练

Agent 同时面对长期记忆和眼前上下文时，很难一上来就用好整套记忆工具。AgeMem 采用分阶段训练：
1. 练长期记忆——判断什么值得新增、什么是修正
2. 练短期管理——过滤和摘要
3. 把长期检索与短期整理放进复杂任务

### 记忆单元的结构、时序和压缩

**SimpleMem** 不存储原始文本，而是存储压缩后的"记忆单元"。基于亲和力评分在后台异步执行递归固化，将高亲和力的记忆单元合并为更高层级的抽象表征。据说在长时序多轮对话任务上以约 1/10 的 token 消耗击败了全量上下文。

**时序记忆**："拜登是美国总统"在 2024 年可能没什么问题，2026 年就不对了。Zep 及其引擎 Graphiti 引入了时序知识图谱，对边加入时间标注（Temporal Validity），在检索时结合查询时间语境动态合成"当前时刻"的真值图谱。在其报告的长时序评测上可提升 18.5% 准确率。

**分层记忆（MemWeaver）**：同一段历史需要不同抽象——图记忆（关系）、经验记忆（模式）、片段记忆（原文）。三者都来自同一段历史，却服务于不同问题。

### 程序性记忆：从"知识"到"技能"

事实记忆回答"是什么"，长程任务还需要"怎么做"。**ProcMEM** 用 Skill-MDP 描述技能：触发条件→动作序列→终止条件。用 PPO 风格门控做反事实验证，确保新技能不偏离旧技能太远。

### 记忆整合层

**LycheeMemory**：把外部内容变成潜层 Token，以接近 KV-Cache 的形式注入注意力计算，减少文本编解码开销。
**MemAdapter**：从图谱中取出相关局部子图，对齐到模型的语义空间，不用微调主模型也能融合异构记忆。

## 五、架构五件套

1. **内核（Kernel / Control Plane）**：System 2 的慢回路与调度器，决定何时检索/写入/更新
2. **文件系统（File System / Storage Plane）**：Raw Ledger + Views，承载时序一致性与语义压缩
3. **可执行文件（Executable / Skill Plane）**：把经验固化成可复用的程序性单元
4. **总线接口（Interface / Context Bridge）**：记忆与推理之间的接口层，低开销低失真地注入
5. **学习引擎（Learning Engine）**：在不更新权重的前提下，把交互反馈转为改进信号

## 六、工程落地：PowerMem

PowerMem（[GitHub](https://github.com/oceanbase/powermem)）是这套 Memory OS 的开源工程落点，面向 AI Agent 提供持久化、自演化的记忆能力。

**会话结束，状态还在**：持久化记忆、用户画像和作用域管理，记忆可按用户与 Agent 隔离。

**多模态检索**：向量检索、全文检索、图检索、新近度信号参与混合检索——对应 Views 的设计。

**生命周期管理**：大模型参与记忆抽取、更新、合并，结合艾宾浩斯式时间衰减调整优先级。

**经验→技能蒸馏**：Experience 保存经验，Skill 把反复验证的经验整理成可复用的做法。

**多入口接入**：提供 Python SDK、HTTP 服务、MCP 和 CLI，支持 OceanBase、SQLite、PostgreSQL 等后端。

一个长期运行的 Agent，可以顺着几个问题检查自己的记忆系统：
- 会话结束后状态还在不在？
- 历史是否只有向量这一种查法？
- 旧事实能否更新，低价值内容会退场吗？
- 成功经验能沉淀成技能吗？
- 多个应用能共用同一套记忆底座吗？

## 七、2026 全面综述：Memory for Autonomous LLM Agents

arXiv [2603.07670](https://arxiv.org/abs/2603.07670)（[HTML 全文](https://arxiv.org/html/2603.07670)）是一篇 2026 年初发表的全面综述，覆盖了 2022–2026 年 Agent Memory 领域的核心进展。它提供了一个与前三节互补的视角：用 **POMDP** 形式化重新组织了整个领域，并给出了系统化的三维分类学。

### 7.1 形式化：Write-Manage-Read 循环

将 Agent 循环写成：

- $a_t = \pi_\theta(x_t, \mathcal{R}(M_t, x_t), g_t)$
- $M_{t+1} = \mathcal{U}(M_t, x_t, a_t, o_t, r_t)$

其中 $\pi_\theta$ 是策略（LLM），$\mathcal{R}$ 从记忆读取，$\mathcal{U}$ 写入并管理记忆，$g_t$ 是目标，$o_t$ 是环境反馈，$r_t$ 是奖励信号。

关键洞察：$\mathcal{U}$ 不是简单 append — 它要摘要、去重、打分优先级、消解矛盾、适时删除。且 $\pi_\theta$ 与 $(\mathcal{R}, \mathcal{U})$ 构成因果闭环：决策决定写什么，写什么又塑造未来决策。

### 7.2 三维分类学

**时间范围（Temporal Scope）：**
- **Working memory**：上下文窗口内的内容，完美召回但容量有限
- **Episodic memory**：具体的交互记录（工具调用、对话轮次、环境观察），带时间戳和重要性评分
- **Semantic memory**：去上下文的抽象知识（"用户偏好 DD/MM/YYYY"），需主动固化
- **Procedural memory**：可复用的技能和可执行计划（Voyager 的技能库）

**表示底层（Representational Substrate）：**
- **Context-resident text**：摘要、scratchpad，零基础设施但容量受限
- **Vector-indexed stores**：稠密嵌入 + 近似最近邻搜索，可扩至百万级但丢失结构化关系
- **Structured stores**：SQL/知识图谱，保关系但需预定义 schema
- **Executable repositories**：代码库/工具定义，可直接调用

**控制策略（Control Policy）：**
- **Heuristic control**：硬编码规则（top-k、每 n 轮摘要）
- **Prompted self-control**：记忆操作作为工具暴露给 LLM，由 LLM 决定何时调用（MemGPT 方式）
- **Learned control**：记忆操作作为策略动作进行端到端优化（AgeMem 的三阶段 RL）

### 7.3 五大机制家族

| 机制 | 代表工作 | 核心思想 | 风险 |
|------|---------|---------|------|
| Context-resident compression | Self-Controlled Memory | 摘要/滑动窗口/层次摘要 | 摘要漂移：低频关键信息逐轮消失 |
| Retrieval-augmented stores | RAG, RET-LLM | 外部存储 + 检索注入 | 检索质量瓶颈：趋近而非有用 |
| Reflective self-improvement | Reflexion, ExpeL, Generative Agents | 自然语言事后复盘、聚类反思 | 自强化错误：错误信念固化 |
| Hierarchical virtual context | MemGPT, JARVIS-1 | OS 虚拟内存式分页管理 | Orchestration 失效：分页错误无声积累 |
| Policy-learned management | AgeMem (Agentic Memory) | RL 训练记忆操作策略 | 训练成本高、可解释性差 |

### 7.4 评测变迁：从 Recall 到 Agentic Utility

这篇综述追踪了 Memory 评测的演进趋势：

| Benchmark | 年份 | 多会话 | Agentic 任务 | 遗忘测试 | 关键发现 |
|-----------|------|--------|-------------|---------|---------|
| LoCoMo | 2024 | ✓ | – | – | RAG 依然远落后人类，尤其时序因果 |
| MemBench | 2025 | – | – | – | 区分事实记忆 vs 反思记忆 |
| MemoryAgentBench | 2025 | – | – | ✓ | 无系统同时掌握 4 项认知能力 |
| MemoryArena | 2026 | ✓ | ✓ | – | LoCoMo 满分模型在此仅 40–60% |

核心结论：**Long context ≠ memory**、**检索质量是瓶颈**、**遗忘评估被严重忽略**、**跨会话一致性仍是开放挑战**。

### 7.5 工程现实与开放挑战

综述花了大量篇幅讨论工程现实——写路径过滤、矛盾处理、延迟预算、隐私治理——以及开放挑战：

- **Continual consolidation**：如何在不灾难遗忘的前提下持续固化
- **Causally grounded retrieval**：通过因果关系而非语义相似度召回
- **Trustworthy reflection**：反思时不能固化错误信念
- **Learned forgetting**：学会安全遗忘过时信息
- **Standardized evaluation**：社区缺乏 GLUE 式的共享评测体系

最后一句值得全文引用：

> **If there is one takeaway from this survey, it is that memory deserves the same level of engineering investment as the LLM itself.** Model selection gets months of careful benchmarking; memory architecture often gets an afternoon. The evidence reviewed here suggests that flipping this priority—treating memory as a first-class system component worthy of dedicated design, testing, and optimization—may be the single highest-leverage intervention available to agent builders today.

## 八、参数化知识：压缩进权重的记忆

前面几节都在讨论"外部状态"（Ledger / Views / Policy），这一节回到记忆的另一极：**参数化知识**。Agent 的 System 1 本身就是一台被预训练压缩过的机器——它知道什么、不知道什么、先验偏向哪里，全都写在权重里。理解参数化知识的压缩原理、注入方式和先验局限，才能理解为什么外部记忆不是"锦上添花"而是"必需"。

### 8.1 参数化知识的本质：以解码器 Transformer 为例

#### 训练原理：把语料分布压进参数

以 GPT 系列为代表的 decoder-only Transformer 是自回归模型。给定 token 序列 $x = (x_1, \dots, x_T)$，联合概率被分解为：

$$

p_\theta(x) = \prod_{t=1}^{T} p_\theta(x_t \mid x_{<t})

$$

训练目标是最大化整个训练语料的对数似然，等价于最小化交叉熵损失：

$$

\mathcal{L}(\theta) = -\frac{1}{T}\sum_{t=1}^{T} \log p_\theta(x_t \mid x_{<t})

$$

其中每一层的计算是残差结构：先做多头注意力（MHA），再做前馈网络（FFN），各自带 LayerNorm 与残差连接。单个注意力头的核心运算是：

$$

\text{Attn}(Q, K, V) = \text{softmax}\!\left(\frac{QK^{\mathsf{T}}}{\sqrt{d_h}}\right) V

$$

$$

Q = XW_Q, \quad K = XW_K, \quad V = XW_V

$$

FFN 则通常是门控结构：

$$

\text{FFN}(x) = W_2 \cdot \sigma(W_1 x)

$$

知识正是通过梯度下降被"写入"这些权重矩阵的。反向传播计算 $\nabla_\theta \mathcal{L}$，优化器（如 AdamW）按 $\theta \leftarrow \theta - \eta \cdot m / \sqrt{v + \epsilon}$ 更新参数。整个过程可以概括为：**语料中的共现统计被压缩进 $W_Q, W_K, W_V, W_O, W_1, W_2$ 与 embedding 矩阵**。

#### 分布式表征：知识不落在单个神经元上

训练完成后，一条知识（如"中国的首都是北京"）**并不存在某个具体参数里**。它表现为一组参数的联合激活模式：

- 注意力头负责把"中国""首都"等信息搬运到最后一个 token 的位置；
- MLP 神经元（knowledge neuron）在特定上下文触发时把特征映射到"北京"；
- 一个神经元常常同时参与多条知识的计算（多义性 polysemanticity），一条知识也常常由多个参数共同支撑（叠加 superposition）。

这就是**分布式表征**：知识是参数空间中低维子流形上的激活模式，而不是查表项。它的好处是参数利用率高、泛化能力强；代价是**不可寻址、不可审计**——你无法问模型"你哪几个参数存着'北京是首都'"。

#### 先验分布：模型即先验

从贝叶斯视角看，训练得到的 $p_\theta$ 是对训练数据分布 $P_{\text{data}}$ 的估计。**模型学到的知识 = 压缩进参数的条件分布**；模型对某个问题的回答，本质上是采样自这个先验：

$$

p_\theta(x_t \mid x_{<t}) \approx P_{\text{data}}(x_t \mid x_{<t})

$$

因此有两个直接推论：

1. **知识截止日期是硬边界**：训练停在哪天，先验就冻结在哪天。2026 年之后发布的行业新规、新产品参数，模型从未见过，先验里就没有它们。
2. **先验顽固（prior stubbornness）**：模型对高频出现的旧模式有很强偏好。注入少量新知识后，模型面对冲突时会"倒向"训练分布中的旧答案——这正是知识编辑与微调困难的根本原因。

### 8.2 参数化知识的注入：四条路径

既然知识在权重里，更新知识就要改权重。按"改动规模从小到大"排列：

#### 路径一：继续预训练（Continual Pre-training / DAPT）

在领域语料上继续跑 8.1 的交叉熵损失。数学形式完全相同，只是数据换成垂直领域文本（如金融公告、法律文书）。原理是**继续移动先验**：让 $P_{\text{data}}$ 从通用语料迁移到目标分布。

优点：知识密度高时效果好（如"持续预训练让金融模型认识财报术语"）。
缺点：

- **灾难性遗忘（catastrophic forgetting）**：新语料覆盖旧知识，通用能力倒退；
- **成本高**：需要与预训练同量级的算力，且学习率必须压得很低；
- **知识穿越（knowledge traversal）**：每次前向都要穿过全部参数，为读一条知识付出全模型计算。

缓解遗忘的常见做法是在损失里混合旧语料（replay）或加正则项，如 EWC：

$$

\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{new}} + \frac{\lambda}{2}\sum_i F_i (\theta_i - \theta_i^{*})^2

$$

其中 $F_i$ 是 Fisher 信息矩阵对角元，惩罚偏离旧参数的行为。

#### 路径二：监督微调（SFT）

在指令-回答对 $(x, y)$ 上继续优化交叉熵：

$$

\mathcal{L}_{\text{SFT}} = -\frac{1}{|y|}\sum_{t} \log p_\theta(y_t \mid x, y_{<t})

$$

原理：SFT 主要调整**行为分布**（学会回答问题、遵循格式），而不是**事实知识**。当数据里重复出现"（问题，新事实答案）"时，它也能写入一些新知识，但效率远低于预训练——因为梯度信号只在回答位置回传，且容易把"新知识"记住成"格式套路"。

#### 路径三：局部知识编辑（Knowledge Editing）

典型代表是 ROME（Rank-One Model Editing）与 MEMIT。它先通过因果追踪定位存储某条事实的 MLP 层，再对那一层的权重做低秩修正。核心是求解一个带约束的最小二乘问题：

$$

W^{*} = \arg\min_{W} \left\| W K_0 - V_0 \right\|^2 \quad \text{s.t.} \quad W k_* = v_*

$$

其中 $k_*$ 是"（主体，关系）"的键向量，$v_*$ 是要写入的新答案值向量，$(K_0, V_0)$ 是保持不变的其余记忆。闭式解是：

$$

W^{*} = W_0 + (v_* - W_0 k_*) \frac{k_*^{\mathsf{T}} K_0^{\mathsf{T}}}{(K_0^{\mathsf{T}} K_0)^{-1} + k_*^{\mathsf{T}} K_0^{\mathsf{T}}}

$$

（ROME 的 rank-1 版本退化为 $W \leftarrow W + (v_* - W k_*) k_*^{\mathsf{T}} / (k_*^{\mathsf{T}} k_*)$。）

优点：**单条知识秒级更新、不改变其他行为**。缺点：

- **涟漪效应（ripple effect）**：改一条事实可能波及相关推理；
- **规模化后遗忘**：连续编辑成百上千条后，模型出现渐进遗忘甚至灾难性遗忘；
- **知识定位不总是准确**：并非所有知识都干净地落在一个 MLP 层里。

#### 路径四：参数高效微调（PEFT，如 LoRA）

LoRA 的核心假设：**模型微调时的参数变化 $\Delta W$ 是低秩的**。于是不直接改 $W_0$，而是引入两个小矩阵 $B \in \mathbb{R}^{d \times r}$、$A \in \mathbb{R}^{r \times k}$（$r \ll \min(d,k)$）：

$$

W' = W_0 + \Delta W = W_0 + BA

$$

训练时冻结 $W_0$，只优化 $A, B$。推理时可以合并回 $W_0 + BA$，零额外延迟；也可以把不同任务的 LoRA 插拔式切换，互不干扰。

数学原理：低秩分解把可训练参数量从 $d \times k$ 降到 $r(d+k)$（例如 4096×4096 矩阵配 $r=16$，参数量降到原来的 1/256）。由于 $W_0$ 的奇异值谱高度倾斜（前几个奇异值占据主要能量），在它附近只需要低秩扰动就能到达任务的最优区域。

**注入方式的取舍对照**：

| 路径 | 改动对象 | 单条知识成本 | 通用能力保持 | 时效性 |
|------|---------|------------|------------|--------|
| 继续预训练 | 全部权重 | 极高 | 中（需 replay） | 好 |
| SFT | 全部权重 | 中 | 中 | 中 |
| 知识编辑 | 单个 MLP 层 | 极低 | 好（但批量会退化） | 好 |
| LoRA | 低秩增量 | 低 | 好 | 中（需按任务切换） |

### 8.3 先验分布的缓解：三个侧面

先验顽固是参数化记忆的"阿喀琉斯之踵"，缓解手段分三个侧面：

#### 训练侧：移动先验

直接改变 $P_{\text{data}}$，让新知识成为高频。手段包括继续预训练、领域数据混合、数据重加权、课程学习。这是唯一能**真正改写先验**的方式，但成本最高、最慢，且永远追不上知识产生的速度。

#### 推理侧：条件覆盖先验

不改权重，在推理时把新知识放进上下文，让条件概率被证据主导：

$$

p_\theta(x_t \mid x_{<t}, \text{evidence})

$$

即 RAG / 上下文注入。这是当前工业界缓解知识滞后的主力手段——新知识只要写进检索库即可生效，零训练成本。缺点是：上下文窗口有限、检索质量决定上限（"趋近而非有用"）、长上下文存在 lost in the middle 现象。解码侧还可以用上下文感知解码（context-aware decoding），在采样时压制与证据冲突的先验 token。

#### 后验侧：对后验做手术

介于两者之间：不动整体训练，直接修正后验分布的关键位置。知识编辑（8.2 路径三）就是在后验上做局部手术；LoRA 切换则可以理解为"把多个后验版本并存，按任务选择"。后验侧手段快、准，但规模化后的可靠性仍是开放问题。

**一个关键认识**：三个侧面不是互斥的，而是按"知识的使用频率与时效性"分工——高频稳定知识走训练侧写进先验；中频时效知识走后验侧；低频、易变、高保真需求的知识走推理侧注入。

### 8.4 基于读写效率的记忆分层：Memory3 的形式化

这一小节的数学与原理来自《记忆工程》参考文献 [1]（即 [Memory3 论文](https://arxiv.org/abs/2407.01178)，arXiv:2407.01178，[PDF](/papers/memory3-explicit-memory.pdf)）。它给出一个非常干净的观察：**知识应该存在哪种记忆格式，取决于读写成本与使用频率的权衡**。

把 LLM 的一生看作"把知识从原始数据搬运到计算"的过程，总成本写作：

$$

\sum_{\text{knowledge } k} \min_{\text{format } m} \Big[ \text{cost}_{\text{write}}(k, m) + n_k \cdot \text{cost}_{\text{read}}(k, m) \Big]

$$

其中 $\text{cost}_{\text{write}}$ 是把知识 $k$ 编码进格式 $m$ 的成本，$\text{cost}_{\text{read}}$ 是推理时把 $k$ 从格式 $m$ 读入计算的成本，$n_k$ 是这条知识在模型生命周期内的期望使用次数。

Memory3 用 2.4B 模型实测了三种格式的 TFlops 成本（详见附录 A 的推导）：

$$

\begin{cases}
c_{\text{implicit}}(n) \ge 2.24 & \text{（模型参数）}\\
c_{\text{explicit}}(n) = 0.308 + 0.000144\, n & \text{（显式记忆）}\\
c_{\text{external}}(n) \ge 0.624\, n & \text{（RAG 纯文本）}
\end{cases}

$$

解读：

- **模型参数（implicit）**：写入 = 训练（约 2.24 TFlops/条），读取 ≈ 0（矩阵乘法顺带完成）。参数每次前向都被遍历，读成本与使用次数无关；
- **RAG 文本（external）**：写入 = 0（存文本不花钱），读取 = 每次都要重新编码并塞进上下文（约 0.624 TFlops/次），用得越多次越贵；
- **显式记忆（explicit）**：写入一次约 0.308 TFlops，读取极便宜（约 $1.44 \times 10^{-4}$ TFlops/次）。

由此得到**记忆分层**：plain text (RAG) → explicit memory → model parameters，越往上写成本越高、读成本越低。对单条知识，选择使总成本最小的格式。令三种成本曲线两两相交，得到显式记忆的最优区间：

$$

n \in (0.494,\ 13400)

$$

即：**一条知识若在一生中被使用约 0.5 次到 1.34 万次之间，显式记忆是最优解**——用得极少就放 RAG（写零成本），用得极多就固化进参数（读零成本），中间地带全部交给显式记忆。

这套分层与人类记忆高度同构：常见表达（implicit，肌肉记忆式随取随用）、读过的书（explicit，需要时回忆）、开卷考试翻资料（external，现查现用）。

### 8.5 基于注意力键值对的显式记忆：训练与推理

Memory3 的显式记忆实现极为优雅：**直接复用 Transformer 自注意力层的 Key-Value 向量**，不增加任何新参数。

#### 写入（记忆编码）

每条参考文本（≤128 token）独立前向编码，从自注意力层的 KV 中"摘取"最有信息量的部分：

- **层稀疏**：只取前 22 层（共 44 层）作为 memory layers；
- **头稀疏**：GQA 下 8 个 KV head 全部作为 memory heads（40 个 query head 共享）；
- **token 稀疏**：对每个 head，按注意力权重聚合分数选 top-8 token（128 选 8）。token 重要性定义为该 token 从所有位置收到的注意力之和：

$$

w_j^{l,h} = \sum_{i=0}^{127} \tilde{a}_{i,j}^{l,h}

$$

- **维度压缩**：可选向量量化（OPQ20x80-Residual2x14-PQ8x10），把 80 维 bf16 压到 14 维 uint8，压缩率约 11.4 倍。

最终每条记忆的形状是 $(22,\ 2,\ 8,\ 8,\ 80)$（memory layers, key/value, KV heads, sparse tokens, head dim）。整体稀疏度约 160x（不加量化）到 1830x（加量化）：原始显式记忆库约 7.17 PB，压缩后降到 45.9 TB 或 4.02 TB，可以放进 GPU 集群的磁盘。

#### 读取（推理注入）

推理时，每生成 64 个 token 就用当前片段做 query，通过 BGE-M3 嵌入 + FAISS 做余弦相似度检索，取回 5 条显式记忆，**把它们的 KV 直接拼接到自注意力的 KV 序列上**：

$$

Y_i^{l,h} = \text{softmax}\!\left( \frac{X_i^{l,h} W_Q^{l,h} \cdot \text{concat}\!\left( K_0^{l,h}, \dots, K_4^{l,h},\ X_{[:i]}^{l,h} W_K^{l,h} \right)^{\mathsf{T}}}{\sqrt{d_h}} \right) \cdot \text{concat}\!\left( V_0^{l,h}, \dots, V_4^{l,h},\ X_{[:i]}^{l,h} W_V^{l,h} \right) W_O^{l,h}

$$

记忆采用并行位置编码（所有记忆 KV 共用同一 128 区间），避免"lost in the middle"；token 稀疏化在 RoPE 之后做，保留相对位置。

#### 为什么是高保真映射

这是显式记忆与参数化记忆的本质区别：

- **参数化记忆**是**有损压缩**——知识被编码进分布式权重后，细节丢失、无法审计、先验固化；
- **显式记忆**是**无损引用**——KV 直接来自参考文本的编码，与原文之间保持一一对应（key 决定"何时被想起"，value 决定"想起什么"）。答案可以从记忆中高保真地"抄"出来，而不是从先验里"猜"出来。

评测印证了这一点：Memory3-SFT（2.4B）在 HaluEval / TruthfulQA / HalluQA 上平均 48.60 分，显著超过同规模的 Phi-2（38.31）、Gemma-2B（38.04），甚至超过 Falcon-40B（35.37）等大模型。

#### 训练：两阶段预训练

Memory3 的预训练分两段：

1. **Warmup 阶段**：普通预训练，不注入记忆。直接带显式记忆从头训练会让模型学会"忽略记忆"（模型太弱时无法理解自己生成的记忆，注意力层会学成无视它们）；
2. **Continual train 阶段**：在训练序列前拼接检索到的参考（每序列 32 chunk × 128 token = 4096 参考 token），实时编码成显式记忆参与自注意力。为防止泄漏，要求训练序列与参考的重叠 < 90%。

两阶段让模型学会"写记忆"和"读记忆"，而具体知识本身大多外置——这正是 8.4 分层思想在训练目标上的体现：**让参数只学抽象知识，让具体知识留在记忆库里**。

#### 行业落地的意义

在专业任务（法律 JEC-QA、医学 C-Eval/MMLU）上，Memory3 验证了一个关键特性：**适配新领域只需往知识库里导入该领域的参考文本**（法规、医学书籍），把参考转成显式记忆即可推理，**完全不需要微调**。对比参数化路径（8.2 的四条路径都要动权重、承担遗忘与成本），这是"知识更新频率与成本"问题的一个结构性答案。

### 8.6 讨论：仅靠知识注入能解决行业知识滞后吗？

回到本文开头的命题——"过去有没有帮它把今天的事做对"。行业知识滞后是参数化记忆的天然缺陷，那么**仅靠知识注入与更新（8.2 的四条路径）能完美解决吗？答案是否定的**，原因有四：

1. **成本追不上速度**：知识产生是连续的（新规、新版本、新产品），而参数化更新的成本是离散且高昂的（单条知识预训练写入约 2.24 TFlops，SFT 需要成对数据，知识编辑有规模化遗忘）。把"持续产生的事实"全部塞进权重，在经济学上不可持续。

2. **先验顽固导致吸收不良**：模型对训练分布的高频模式有强先验。行业新知识与旧先验冲突时，微调后的模型常常"假装学会"——评测集上答对，开放场景下又倒向旧答案。**模型能"记住"新知识，不等于能"消化"新知识**：消化需要新知识与既有知识结构建立连接，而参数化的局部更新很难保证这一点。

3. **单一格式不满足所有知识**：8.4 的成本公式说明，不同使用频率的知识各有最优格式。高频稳定知识适合进参数，低频易变知识进参数是浪费；反之，把高频知识放 RAG 每次重编码也是浪费。**只靠一种格式（无论参数还是 RAG）都无法全局最优**。

4. **可观测性为零**：参数化知识不可寻址、不可审计、不可回放。行业场景要求"这个回答依据的法规是哪条"，参数化记忆给不出 provenance；显式记忆与参考文本一一对应，天然可溯源。

因此，对行业知识滞后问题的务实答案是**分层记忆**：

- **高频、稳定、需要内化的知识** → 继续预训练 / LoRA 写进参数（先验）；
- **中频、时效、需要可溯源的知识** → 显式记忆（Memory3 式的 KV 记忆库），更新 = 更新知识库，零训练；
- **低频、一次性、高保真要求** → RAG / 上下文注入。

一句话总结：**参数化知识决定了模型"生来会什么"，显式记忆决定了模型"此刻知道什么"，而好的 Memory OS 负责让两者按读写效率各得其所。** 只靠把知识塞进权重，既塞不起，也消化不好，更追溯不了。
