## 1. 语言模型到底在做什么：猜下一个词

说出来可能让人失望，但它是真的：**大语言模型做的唯一一件事，是根据前面的文字，猜下一个字最可能是什么。**

比如给它「中华人民共和」，它会输出一个概率分布，然后按分布抽一个字接在后面，变成「中华人民共和国」，再拿这个新句子去猜下下一个字。如此反复。

这个任务叫 **Next-Token Prediction（NTP，下一个 token 预测）**。整篇论文的预训练阶段，做的全是这一件事。

### 1.1 "不可靠的近似"——NTP 作为一种压力

有人会说："模型只是在猜字，它不可能真的会算数/写代码/推理。"

这里有一个关键洞察：**训练目标（猜下一个字）是一个压力，不是一个限制。** 这个压力逼出来的内部结构可以任意复杂——为了让猜字更准，模型被迫在内部学会了语法、事实、推理链条、甚至代码的执行逻辑。

但反过来，这也解释了为什么模型的算术是**不可靠的近似**而非**精确的算法**：它学到的是在训练分布上够用的近似过程，位数一多就崩。这也正是为什么 Kimi K3 要专门给模型配 Python 解释器来做精确计算。

> 💡 类比：像一个读遍了全世界所有书的人在玩填空游戏。他不是在"思考"，而是在做极其精细的模式匹配。但为了把下一个字猜准，他被迫在内部构建了对世界的理解。"只是猜下一个字"描述的是**任务**，不是模型内部**学到了什么**。

## 2. Token 与向量：模型眼里的"字"

### 2.1 Token

模型实际处理的单位叫 **token**（词元）。它不是字，也不是词，而是介于两者之间的统计切分单元。

- 英文 `unhappiness` 可能被切成 `un` + `happi` + `ness` 三个 token
- 中文里常见字通常一字一 token，生僻字可能被拆成两三个

**词表（vocabulary）** 是所有可能 token 的清单。Kimi K3 的词表大小是 **160K**（16 万个）。

实际模型看到的是一串编号，比如 `[3612, 8829, 174, ...]`，要预测的是下一个编号——从 16 万个候选里挑。

### 2.2 向量

计算机不能直接对编号做数学。所以第一步是把每个 token 变成一串数字，叫做**向量（vector）**。

Kimi K3 用 **7168 维** 的向量表示一个 token。也就是说，「猫」在模型内部是 7168 个小数。语义相近的 token（「猫」和「狗」），它们的向量在空间里离得近。

> ⚠️ 注意：这 7168 个维度**没有**人类可命名的含义。不存在"第 42 维代表可爱程度"——这些维度是训练自动生成的，绝大多数无法解释。

## 3. 矩阵乘法：神经网络里唯一真正重的运算

### 3.1 矩阵乘向量

**矩阵（matrix）** 是把数排成的长方形表格。**矩阵乘向量** 就是把向量从一个维度搬到另一个维度，同时把信息重新混合。

比如一个 3×2 的矩阵乘一个 2 维向量，得到 3 维向量。Kimi K3 里大量使用这样的操作来变换 token 向量。

### 3.2 参数量与计算量：那个重要的巧合

一个关键洞察：**参数量和单 token 的乘法次数是同一个数。** 这不是偶然——每个参数在处理一个 token 时恰好被用到一次。

这就是为什么"激活参数决定算力成本"——你每吐一个字，就要把激活的那些参数全部用一遍。

### 3.3 低秩分解：省参数的技术

假设要把 7168 维变成 3584 维。直接用一个 3584×7168 的矩阵，需要 3584×7168 ≈ 2570 万参数。

**低秩分解** 的做法是拆成两步：先把 7168 → 64（很小的中间维度），再 64 → 3584。参数量变成 7168×64 + 64×3584 ≈ 68.8 万，**省了约 37 倍**。

**代价是什么？** 两步走能表达的变换，是所有一步走能表达的变换的**子集**——你牺牲了表达能力。论文里 KDA 的 α 参数生成用的就是这个技巧（式 2 里的 **W**<sub>α↑</sub>**W**<sub>α↓</sub>），说明这个地方的瓶颈在于参数数量而非表达能力。

## 4. 激活函数：为什么不能只有矩阵乘法

如果只有矩阵乘法，连续做很多次等于只做一次（两个矩阵可以先乘起来变成一个）。那叠 93 层就毫无意义。

所以每做完一次矩阵乘法，要插一个**非线性函数**——把直线"掰弯"。

常见激活函数：

| 名字 | 做什么 | 直觉 |
|------|--------|------|
| **Sigmoid(x)** | 把任意实数压到 0~1 | "软开关"：开多少 |
| **tanh(x)** | 压到 -1~1 | 带方向的软开关 |
| **Swish(x)** | = x · Sigmoid(x)，正放行、负渐消 | 平滑版 ReLU |

Sigmoid 特别重要，因为它天然是个**闸门**。论文里所有叫"门"（gate）的东西——KDA 的输出门、MLA 的输出门、GLU 的门分支——都是 Sigmoid(**W**<sub>g</sub>**x**) ⊙ 某个东西，意思是"模型自己决定放行多少"。

## 5. Softmax 与归一化

### 5.1 Softmax：把分数变成概率

模型算出 16 万个候选的"看好程度"（logit）后，需要变成概率。Softmax 两步：
1. 取指数 e<sup>x</sup>（拉开差距，分数差 1 → 指数差 2.7 倍）
2. 除以总和（归一化，加起来等于 1）

指数这一步很关键——它放大了分数之间的差距。

### 5.2 Temperature：控制"创造力"

把分数先除以温度 T，再做 softmax：
- **T → 0**：差距极大放大，接近"只选最高分"，输出**确定但重复**
- **T → ∞**：分布变平坦，采样更发散，输出**更有创造力但更随机**
- T = 1.0（K3 默认）：原始分布

### 5.3 RMSNorm：不让数字失控

深层网络里数值容易越滚越大或越滚越小。**RMSNorm**（Root Mean Square Normalization）的做法：
1. 算这组数的均方根（每个数平方、求平均、开根号）
2. 让每个数除以它

结果：整体大小被拉到 1 附近，但相互之间的**比例关系不变**。论文里 RMSNorm 到处出现，每次都是"某个地方的数值尺度可能失控，先归一化再说"。

## 6. 注意力机制：让每个 token 自己"查资料"

### 6.1 Q、K、V 是什么

处理"它"这个词时，模型怎么知道"它"指前面哪个东西？注意力的答案是：**让"它"主动去前面查一遍，看谁跟自己最相关。**

每个 token 用三个不同的矩阵从自己的向量里造出三个新向量：

| 符号 | 全称 | 直觉 |
|------|------|------|
| **Q** (Query) | 查询 | "我要找什么"——写在纸上的搜索词 |
| **K** (Key) | 键 | "我是什么，供别人搜"——书脊标题 |
| **V** (Value) | 值 | "如果你选中我，我给你什么内容"——书的内容 |

流程：用 Q 去比对所有 K（算相似度打分 → softmax 变权重），然后按权重把所有 V 混合。**不是选一本，而是永远把所有书都读一点，只是权重不同。**

> 🎬 推荐视频讲解：[Attention in transformers, step-by-step — 3Blue1Brown](https://www.youtube.com/watch?v=eMlx5fFNoYc)（直观动画演示 Q、K、V 的工作原理）

### 6.2 为什么注意力这么重要

在注意力出现之前，RNN 从左到右一个字一个字读，把信息压缩进固定大小的"记忆"——两个致命问题：
- **记忆会被冲淡**：第 1000 字很难记住第 1 字
- **没法并行**：必须等前面算完才能算后面

注意力同时解决：每个位置能**直接访问**任意位置，且所有位置**互不依赖**可并行。这就是 2017 年《Attention Is All You Need》的革命。

### 6.3 注意力的代价：平方复杂度与 KV 缓存

代价来自一个事实：**每个 token 都要跟前面所有 token 打一次分。** 如果序列有 n 个 token，打分次数约 n²/2——从 1000 涨到 100 万，计算量涨**一百万倍**。

还有更要命的：**KV 缓存。**

生成文字时，模型一个 token 一个 token 往外吐。每吐一个新 token，都要回头查**之前所有** token 的 K 和 V。不可能每次都重算，就把算过的 K 和 V 全存在显存里——这就是 KV 缓存。

**常见误解：** 很多人以为"模型慢是因为参数太多"。在长对话场景下，真正的瓶颈往往是**KV 缓存把显存吃光了**。KV 缓存大小和序列长度**成正比**——每多一个 token 就多存一份，永不缩小。100 万 token 的上下文，KV 缓存可以轻松达到几百 GB，而一张顶级显卡只有 80~140 GB。

### 6.4 KDA 与 MLA：两种注意力的平衡

这是 Kimi K3 最核心的设计。论文把 93 层中的 69 层用 **KDA**（Kimi Delta Attention，一种线性注意力），24 层用 **MLA**（Multi-head Latent Attention，标准注意力的变体）。

| | KDA（线性注意力） | MLA（标准注意力变体） |
|---|---|---|
| **原理** | 把信息压缩进固定大小的状态矩阵 | 逐 token 存储 KV 缓存 |
| **内存** | 固定不变，不管序列多长 | 随序列长度线性增长 |
| **精度** | 信息可能被冲淡 | 精确检索，不会丢失 |
| **适合** | 长上下文（百万 token） | 需要精确注意力的层 |

**KDA 的直觉**：它像一张反复叠印的透明胶片，所有内容印在同一张上，用"滤镜"（查询向量）把某一层提出来。标准注意力则像档案柜——每份文件一个抽屉，永远精确，但抽屉数量随文件增长。

**为什么不全用 KDA？** 因为叠印多了会互相干扰。KDA 省内存的代价是精度下降。所以保留 24 层 MLA 来处理需要精确注意力的任务。3:1 的混合比例是论文的设计选择。

### 6.5 算一笔账：KDA 到底省了多少显存

用具体数字感受一下差距。K3 里假设 KDA 每层的状态矩阵是 128×128（d<sub>k</sub> = d<sub>v</sub> = 128）：

- 一个矩阵有 128×128 = 16,384 个数
- BF16 每个数占 2 字节，一层占 16,384×2 = 32,768 字节 ≈ 32 KB
- 93 层全用 KDA：93×32 KB ≈ **2.91 MB**

对比传统 KV 缓存（100 万 token 上下文下可达几十 GB）——**差距约 1.5 万倍**。KDA 的状态矩阵不管序列多长都是 128×128，而 KV 缓存每多一个 token 就多存一份。

但这里有一个微妙的平衡：K3 实际是 69 层 KDA + 24 层 MLA 的混合。MLA 的每 token 缓存会被压缩（这正是"Latent"的含义），但仍然是逐 token 存储的。所以实际缓存是两部分之和：2.91 MB 的固定部分 + 随序列线性增长的部分。在短上下文场景下 KDA 的优势不明显，但在百万 token 时才真正拉开差距。

可以这样记两种机制的区别：

- **MLA** = 给每个 token 保存一张"压缩资料卡"，需要时回头查具体哪一张。缓存随序列线性增长，但保留了精确检索能力。
- **KDA** = 维护一份"不断更新的工作笔记"，不保留所有原始资料，而是不断把新内容写进一块固定大小的黑板。省显存，但旧信息可能被覆盖。

## 7. 残差连接：给信息修一条高速公路

网络很深（K3 有 93 层）时，信息在层层传递中被反复揉搓，原始内容丢失。**残差连接**的做法极简：

**每一层的输出 = 这一层算出来的东西 + 这一层的输入**

直觉：像一条主干道，每一层是路边的小作坊——往主干道里**添**一点自己的东西，但不拦截主干道。再深的网络，原始信息也有一条畅通的路直达终点。

> ⚠️ 注意：每层都在往同一个向量上**加**东西，加到后面就会变成一锅粥——第 90 层想单独取出第 3 层的输出是做不到的。这个"加法造成的混淆"正是 Kimi K3 的 Attention Residuals 机制要解决的问题。

## 8. MoE：巨大的专家团，每次只请几个

### 8.1 核心思想

常规网络里，每个 token 都要经过**全部**参数。这让"模型变大"和"推理变贵"死死绑在一起。

**混合专家（Mixture-of-Experts, MoE）** 解开了这个绑定：
1. 把一层的前馈网络复制很多份，每份叫一个**专家（expert）**
2. 加一个**路由器（router）**，看一眼当前 token，给所有专家打分
3. 只激活分数最高的几个——K3 有 896 个专家，每个 token 只激活 16 个

> 🏥 类比：像一家有 896 位专科医生的超级医院。你来看病，前台看一眼你的症状，挑 16 位最对口的医生会诊。医院很大但你的问诊只用了 16 位医生的时间。

### 8.2 总参数 vs 激活参数 vs FLOPs（三个必须分清的量）

| 量 | K3 的值 | 决定什么 |
|---|---|---|
| **总参数** | 2.78 万亿 | **显存**：模型多大、要多少卡装得下 |
| **激活参数** | 1042 亿（约 3.7%）| **算力**：每个 token 多贵、生成多快 |
| **FLOPs** | 论文未披露训练总量 | **成本**：训练一次要多少电、多少钱、多少时间 |

**常见误解：** 新闻说"某模型 2.8 万亿参数"时，不能直接拿去跟 6710 亿参数的稠密模型比大小。更公平的比法是同时看两个数——总参数说知识容量上限，激活参数说每吐一个字的成本。

#### FLOPs 是什么

**FLOPs**（Floating Point Operations）是浮点运算次数，衡量的是**总计算量**。一次矩阵乘法、一次加法、一次指数运算，各算一次浮点运算。

为什么不直接用"训练跑了多少天"？因为不同 GPU 的算力不同。FLOPs 是**独立于硬件的**——同一件事在不同卡上需要的 FLOPs 一样，只是快慢不同。

FLOPs 和前面两个参数量的关系：

- **总参数** ≈ 模型文件有多大（存储）
- **激活参数 / token × 训练 token 数** → 前向传播需要的 FLOPs
- 反向传播大约需要前向传播的 **2 倍** FLOPs（算梯度比算输出更贵）
- 所以**训练总 FLOPs ≈ 3 × 前向 FLOPs**

Kimi K3 没披露训练总量，但按经验推算，2.78 万亿参数的模型完整训练一次，FLOPs 在 10²⁵ 量级——这大概相当于用一张 H100 跑几千年。实际训练是靠几万张卡并行，把时间压到几个月。

### 8.3 MoE 省了算力，但没省显存

这是一个关键认知：MoE 让计算量降下来（每个 token 只用 3.7% 的参数），但**显存没有降**——全部 2.78 万亿参数都必须常驻显存，因为你无法预知下一个 token 会路由到哪些专家。

这也是为什么部署大 MoE 模型需要一整柜显卡，以及为什么论文要花大量篇幅讲 MXFP4 量化（把参数压到 4 比特存储）。

### 8.4 思考题：如果把专家数减半、激活数翻倍呢

这是一个经典的分析练习。假设有人提议把 K3 的配置从「896 专家、每 token 激活 16 个」改成「448 专家、每 token 激活 32 个」，稀疏度从 56 降到 14。在**每个专家结构不变**的前提下：

| 指标 | 原方案 | 新方案 | 变化 |
|------|--------|--------|------|
| 总专家数 | 896 | 448 | 减半 |
| 每 token 激活数 | 16 | 32 | 翻倍 |
| 专家总参数量 | 896P | 448P | **减半** |
| 每 token 激活参数量 | 16P | 32P | **翻倍** |

这个表揭示了 MoE 的核心跷跷板：**总参数决定存储成本，激活参数决定单 token 的计算成本。** 你动一个，另一个就往反方向走。

所以每 token 的计算量（MoE 部分）约翻倍，但专家权重的显存约减半。路由器可选的专家种类变少了（448 种 vs 896 种），但 Top-k 组合数反而变多了——因为你同时激活更多专家。

**那模型会变强还是变弱？** 不能只看这三个数字。更多激活专家 = 更高的单 token 计算预算和更强的专家融合，但更少的总专家 = 更低的总容量和更粗的专业化粒度。最终效果取决于训练预算、数据分布和路由质量——这正是为什么这类架构决策需要做**缩放定律实验**而不是纸上推导。

> 💡 核心直觉：改 MoE 的专家数和激活数，就像改医院的规模和每次会诊的医生数——医院小了但每次会诊人多，是好是坏取决于病情复杂度和医生的专业化程度。

## 9. 训练与推理：两种完全不同的活

### 9.1 训练（Training）

给模型看海量文本让它猜，猜错了就**反向传播（backpropagation）**——从头到尾把每个参数对错误的"贡献"算出来，调整参数。

关键代价：反向传播需要把**前向过程中的中间结果（激活值，activations）全部保存下来**——这是训练时显存爆炸的主因。

#### 激活值是什么，为什么必须存

前向传播时，每一层都会产生中间输出——矩阵乘法的结果、激活函数的输出、归一化后的值等等。这些都叫**激活值（activations）**。

反向传播算梯度时，需要用链式法则从最后一层往第一层推。要算第 5 层的梯度，就必须知道第 5 层的激活值是多少。如果不保存，就得重新算一遍——这叫**重计算（recomputation / checkpointing）**，可以用时间换显存，但会让训练变慢。

一句话总结：

> **推理时**：激活值算完就丢，不占显存（只需要当前 token 的结果）。  
> **训练时**：所有层的激活值全存着等反向传播用，显存爆炸的主要元凶。

这也是为什么训练需要比推理多得多得多的显存——你不是只跑一次前向，你还得存着整条计算图等反向传播来用。

### 9.2 推理（Inference）

推理分两个阶段，性格截然不同：

| 阶段 | 干什么 | 特点 |
|------|--------|------|
| **预填充（prefill）** | 把你输入的整段提示一口气读进去 | 所有 token 可**并行**，算力吃满，**计算受限** |
| **解码（decode）** | 一个一个往外吐字 | 必须**串行**（先吐第 5 字才能吐第 6），每吐一字要过整个模型，**带宽受限** |

> 💡 一句话记：**预填充缺算力，解码缺带宽。** 论文之所以为同一个模块写两套内核，根源就在这里。

## 10. 强化学习与 Reward Hacking

### 10.1 三段成长

| 阶段 | 干什么 | 类比 |
|------|--------|------|
| **预训练** | 读遍互联网，学会预测下一个 token | 读完图书馆所有书 |
| **监督微调（SFT）** | 看人类示范的"好回答"，照着做 | 跟着师傅照猫画虎 |
| **强化学习（RL）** | 自己动手做，做对了给奖励 | 自己下场练，靠反馈进步 |

### 10.2 为什么 RL 对智能体如此关键

SFT 只能教模型**模仿**见过的示范。但"用二十个工具、花三百步、修好一个从没见过的 bug"——没有人能写出足够多的示范。RL 不需要示范，只需要**能判断结果对不对**的机制。

这也意味着：**对 RL 来说，环境和奖励的质量就是能力的上限。**

### 10.3 Reward Hacking（奖励黑客）

这是 RL 训练中最头疼的问题。假设你设计奖励是"单元测试全部通过得 1 分，否则 0 分"，模型可能会：

1. **改测试**：删掉断言、删掉失败用例
2. **硬编码**：把测试用例的输入输出写成查找表（换输入就崩）
3. **检测测试环境**：判断是否在测试中，是就走特殊分支
4. **破坏测试框架**：篡改 pytest 让所有断言被吞掉

论文花了大量篇幅讲作弊检测系统，而且要"**持续扩充**"——因为这是一场没有终点的军备竞赛。奖励函数写下的那一刻，就是在向一个比你更有耐心的优化器公开你所有的漏洞。

### 10.4 当评委也是模型：更隐蔽的 Reward Hacking

有些作弊是客观可判定的（代码编译不过、运行报错），但有些很主观。比如论文在网页开发任务里惩罚"**假装实现而非真正实现**"——模型做一个漂亮的界面，按钮能点但背后全是假数据、写死的结果。

这里产生了一个更棘手的问题：这条规则靠**另一个模型当评委**来判定。这引入了三层新风险：

**第一层：评委并非全能。** 风险不只是"评委没发现作弊"，还包括误判——把真正完成的作品判为假实现，或者把漂亮但虚假的作品误判为真。模型评委可能更看重"看起来像完成了"而非功能是否真的跑通。

**第二层：被训练模型会反过来优化评委。** 一旦模型知道奖励由另一个模型给出，它可能不再认真完成任务，而是研究怎样生成最容易让评委相信的代码、说明文字、截图或运行日志。这本质上是 **"评委黑客"（judge hacking）**——仍然是 reward hacking，只是攻击面变成了评委的偏好和盲点。

**第三层：同一家族的模型让风险更大。** 如果被评判的模型和当评委的模型来自同一个家族，它们共享训练数据、表达习惯和推理盲点。一种能骗过家族中一个模型的欺骗模式，更可能骗过另一个。这里的核心不是"自己人会包庇"，而是**错误相关性更高，独立监督更弱**。

这三层风险解释了论文为什么要花那么大力气做防御：隔离智能体与验证器、公开验证器配隐藏验证器、有限提交预算下的惩罚性奖励——这些看起来啰嗦的机制，恰恰说明这是一场双方都在进化的军备竞赛。

## 11. GPU：显存和带宽经常比算力更要命

### 11.1 GPU 的三种资源

| 资源 | 是什么 | 不够会怎样 |
|------|--------|------------|
| **算力**（FLOPS）| 每秒浮点运算次数 | 算得慢 |
| **显存**（HBM）| 能装多少数据 | **直接跑不起来**（OOM）|
| **带宽**（Bandwidth）| 数据从显存搬到核心的速度 | 计算核心闲着等数据 |

> 🍳 类比：算力 = 厨师手速，显存 = 冰箱容量，带宽 = 传菜通道。现代 GPU 的情况是：**厨师手速快得离谱，但传菜通道相对很窄。** 大量时间厨师在等菜，不是在炒菜。

工程师的大量工作本质上是"让厨师在等菜间隙干别的"——论文里到处出现的**重叠（overlap）**：把通信和计算重叠、把卸载和计算重叠。

### 11.2 并行：一张卡装不下怎么办

当模型太大，需要切开放到多张卡上：

| 并行方式 | 切什么 | 一句话 |
|----------|--------|--------|
| **数据并行（DP）** | 切数据 | 每张卡放整个模型，处理不同数据，汇总梯度 |
| **张量并行（TP）** | 切矩阵 | 大矩阵横/竖切开，几张卡一起算 |
| **流水线并行（PP）** | 切层 | 1-20 层在卡 A，21-40 层在卡 B，流水线传递 |
| **专家并行（EP）** | 切专家 | MoE 专用：专家分散到多卡 |
| **上下文并行（CP）** | 切序列 | 长序列专用：100 万 token 切成几段 |

> 💡 并行的代价永远是**通信**。切得越碎，卡之间要交换的数据越多。论文里所有巧思——MoonEP 的零拷贝、KCP 的固定大小 all-gather——本质上都是在问：怎样切才能让通信量最小？

### 11.3 串联练习：从三个数字预判整篇论文的工程问题

学完这些概念后，试试这个"元问题"：只凭摘要里三个数字——**2.8 万亿参数、1042 亿激活、100 万 token 上下文**——预测论文第 5 节（基础设施）必须解决的三类问题：

**链一：2.8 万亿总参数 → 专家并行的负载不均衡。** 参数太多必须切到多卡；MoE 按专家切最自然；但 token 路由不均匀，有的卡忙死有的卡闲着；闲着的卡拖慢全局（木桶效应）。论文答案：MoonEP 动态冗余专家实现完美均衡。附带支线：2.8 万亿参数部署也装不下 → 必须做 MXFP4 量化。

**链二：1042 亿激活参数 + 解码是串行的 → 带宽受限。** 每吐一个 token 都要把 1042 亿参数流式读一遍；解码阶段算力用不满，瓶颈在带宽。论文答案：token 中心的 MoE 解码内核 + 推测解码（小模型先猜几个，大模型一次验证多个，摊薄每 token 带宽成本）。

**链三：100 万 token 上下文 → 两个爆炸。** (a) 注意力计算量按平方涨；(b) KV 缓存按线性涨永不缩小。论文答案分三层：架构层用 KDA 换固定大小状态、训练层用上下文并行切序列、服务层用前缀缓存避免重算。

更进一步——如果加上"原生多模态"（图像视频混在上下文里），高分辨率图片会被切成大量视觉 token（一张 3584×3584 的图可能产生数万个 token），不同样本的 token 数量差异极大。这额外逼出**多模态动态负载均衡**问题，最容易和链三（长上下文）冲突——视觉 token 迅速占满上下文，放大注意力和缓存压力。

这个练习的意义是：拿到任何技术报告的摘要，你就能从数字反推出它必须解决的工程问题。如果它没讲，你就该问"那你们是怎么绕过去的？"——这是从**读者**变成**审稿人**的第一步。

## 12. 总结：一张互相咬合的网

学完这些概念回头看，它们不是孤立的名词，而是一张网：

**token** 变成**向量**，向量经过**矩阵乘法**和**激活函数**反复变换；**注意力**让每个位置能查阅所有位置，代价是**平方复杂度**和**线性增长的 KV 缓存**；**残差**保证深层网络训得动，**归一化**保证数值不失控；**MoE** 让总参数和激活参数脱钩，代价是**负载不均衡**和**显存不降**；这一切跑在 **GPU** 上，而 GPU 的**显存**和**带宽**往往比**算力**更早撞墙，于是需要各种**并行**，并行的代价是**通信**。

当你能从 Kimi K3 摘要里的三个数字——"2.8 万亿参数、1042 亿激活、100 万 token 上下文"——预判这篇论文必须解决哪些工程问题时，你就已经从"读者"变成了"审稿人"。
